# 네 명 편성 정책 — 중복 + 실력

2026-09-18 적용. 추천 목록, 보드 자동편성, 회원 파티의 네 명 선발이 같은 함수를 사용한다. 네 명을 고른 뒤의 2대2 배치는 기존 `pairPlayers`가 담당한다.

## 선택 순서

후보를 한 명씩 고르는 대신 가능한 네 명의 조합을 비교한다. 사용자가 이미 고른 멤버는 고정하고 나머지만 채운다. 아래 항목은 위에서부터 비교한다. 뒤의 점수가 좋아도 앞의 조건을 뒤집지 못한다.

| 순서 | 기준 |
| --- | --- |
| 참가 조건 | 휴식 제외. 콕 확인 기능이 켜져 있으면 미확인 제외. 다른 팀의 멤버·예약자는 보드 후보에서 제외 |
| 성별 구성 | 남4, 여4, 남2여2, 또는 **여성이 4점 이상인 남3여1** |
| 1 | 경기 중인 인원이 가장 적은 조합. 대기자만으로 완성 가능하면 경기 중인 사람을 새로 넣지 않음 |
| 2 | 선택 후 남은 대기자들이 만들 수 있는 허용 경기 수가 가장 많은 조합 |
| 3 | 추천용 판수가 대기자 최저보다 2판 이상 많은 사람의 초과분 합이 가장 작은 조합 |
| 4 | 과거 한 경기와의 최대 공통 인원에 대한 벌점이 가장 작은 조합. 0~1명은 0, 2명은 1, 3명은 2, 4명은 3 |
| 5 | 네 명 사이 6개 쌍의 과거 동반 횟수 합이 가장 작은 조합 |
| 6 | 판수·대기 시간·경기 유형·실력을 합친 보조 점수가 가장 작은 조합 |

대기자만으로 불가능하면 경기 중인 사람이 최소로 필요한 조합을 고른다. 대기자 최소 한 명이 필요하며 보드에서는 나머지를 기존 예약 기능으로 처리한다. 단 보드의 새 예비팀은 경기가 진행 중이고 대기자가 2명 이상이면 특정 경기 중 선수를 예약하지 않고 합류 대기 자리로 남긴다(2026-09-25). 대기 모드를 끈 경우, 이미 있는 팀의 카드 버튼, 코트 그룹은 기존대로 예약한다. 수동으로 고정한 경기 중 멤버는 교체하지 않는다. 충분한 인원이 있어도 성별 조건을 만족하는 네 명이 없으면 자동편성은 실패한다. 후보 자체가 부족하면 기존 동작처럼 완성 가능한 부분 팀을 만들 수 있다.

중복은 완료된 경기의 동반 이력으로 계산한다. 같은 편인지 상대편인지는 구별하지 않는다. 한 과거 경기와 2명이 겹치면 동반 쌍은 1개, 3명이면 3개, 4명이면 6개다. 중복은 최소화 대상이므로 가능한 모든 조합이 겹칠 때 출전을 막지 않는다.

## 보조 점수와 실력 교류

```text
출전 초과분 = Σ max(0, 개인 추천용 판수 − 대기자 최저 판수 − 1)

보조 점수 = Σ(10 × 추천용 판수 − 대기 분 + 경기 중 벌점 30)
          + 경기 유형 반복/전환 항
          + 1.5 × [실력 범위² + 81 × ΔΣ(개인 미교류 연속 출전 / 3)²]
```

- 경기 유형은 남복·여복 계열과 혼복·혼합 계열을 구분한다. 같은 계열 반복은 개인별 +6, 전환은 −6, 이전 경기가 없으면 0이다.
- 경기 중인 사람에게는 대기 시간 혜택을 주지 않는다. 경기 중 벌점은 같은 인원 수끼리 비교할 때 동일하므로 첫 번째 우선순위를 바꾸지 않는다.
- 실력 범위는 네 명의 최고·최저 등급 차이다. 등급 미정(0)은 실력 범위와 실력대 교류 계산에서 제외한다.
- 하위 1~3점은 상위 7~10점, 상위는 하위와 만나면 교류로 센다. 중위 4~6점은 다른 실력대와 만나면 된다. 반대 실력대가 없으면 다른 참가 실력대로 대체하며, 한 실력대만 있으면 교류 벌점이 없다.
- 자기 경기가 완료될 때 교류했으면 개인 연속 횟수를 0으로, 못 했으면 1 증가시킨다. `Δ`는 이 조합이 완료될 경우의 제곱 합 변화다. 오래 만나지 못한 실력대와의 조합에 점점 유리해진다.
- **3은 완화 계수이며 3경기마다 강제 교류하는 보장이 아니다.** 앞선 우선순위와 가능한 조합에 따라 더 오래 걸릴 수 있다.

늦참은 기존 DB 정책이 설정한 추천용 시작 판수(활성 참가자 평균을 반올림)를 사용한다. 이 보정 판수를 실제 동반 이력이나 미교류 횟수로 만들지 않는다. 네 명 선발 정책 자체에는 DB 마이그레이션이 필요하지 않다. 아래 운영진 교대 검사는 별도 RPC 마이그레이션을 사용한다.

## 상태와 적용 범위

경기 중 여부는 코트의 실제 경기 멤버를 기준으로 판정한다. 교류 이력은 경기 ID로 중복을 제거하고 서버 완료 시각 순으로 재구성한다. 기존 `ended_at`, `joined_at`, `wait_since`를 사용하므로 새로고침과 완료 알림 순서가 달라도 같은 완료 이력을 재사용할 수 있다.

과거 휴식·콕 확인 상태의 변경 시각은 저장되어 있지 않다. 현재 참가 가능 상태와 등록 시각을 이용해 당시 존재했던 실력대를 추정한다. 등록 시각은 실제 입장·콕 확인 시각과 다를 수 있다. 서버에 기록되지 않은 현장 휴식은 이 알고리즘만으로 알 수 없다.

추천 후보의 순서는 그 후보를 포함하는 최선의 조합으로 정한다. 여러 우선순위를 하나의 적합도 %로 표현하던 표시는 제거했다. 내부 우선순위 확인 표에는 비교 항목을 표시하며 일반 목록에 새로운 실력 판정 설명을 추가하지 않는다.

기존 수동 편성, 편집 권한, 확정 예약의 생명주기는 유지된다. 경기 종료마다 확정 예약을 자동 해체하거나 팀을 자동 시작하는 스케줄러를 추가한 변경은 아니다. 시뮬레이터는 종료·합류 때 잠정 후보를 다시 계산하므로 전체 앱의 예약 운영까지 동일하다는 의미는 아니다.

2026-09-24부터 뒤 예비팀을 2~3명과 이름 없는 **합류 대기 자리**로 준비할 수 있다. 경기 완료 성공 후 기존 자유 대기자와 복귀자를 대상으로 가능한 예비팀을 네 명으로 완성한다. 채우는 시점은 경기 완료뿐이다(2026-09-25). 빈 코트 매칭 버튼은 대기팀을 채우지 않고, 대기팀 카드는 `완료 후 채움` 비활성 표시다 — 미리 채우면 방금 끝난 사람들이 흩어지지 않아 재회 억제 효과가 사라진다. 빈 코트의 매칭은 자유 대기자로 부족할 때만 미완성 합류 대기팀끼리 재조합하므로, 대기자들이 작은 팀에 묶여 출전 가능한 네 명을 못 만드는 상황을 피한다. 이미 1~3명이 있는 코트 그룹은 그래도 부족하면 기존처럼 경기 중 선수를 예약해 완성하고, 경기 완료 때 대기팀을 채우기 전에 그 그룹이 쓸 사람을 먼저 남긴다. 대기자만으로 네 명이 안 되는 새 예비팀도 특정 선수 예약 대신 합류 대기로 만든다. 일반 수동 팀·완성 팀·특정 선수 예약은 유지한다. 자동 경기 시작은 추가하지 않는다. 세부 조건은 [합류 대기 자리](TEAM_GENERATION_RULES.md#합류-대기-자리-2026-09-24)를 따른다.

2026-09-26부터 숨은 설정으로 지정한 묶음(2~4명) 안의 두 사람은 자동편성에서 같은 경기에 넣지 않는다. 위 우선순위보다 앞서는 강한 제약이며, 직접 함께 배치하거나 추천 창에서 고른 경우는 그대로 둔다. 화면에는 드러내지 않는다. 세부 조건은 [같이 매칭하지 않기](TEAM_GENERATION_RULES.md#같이-매칭하지-않기-2026-09-26)를 따른다.

## 구현과 검증

### 운영진 교대 대기

네 명 선발 후, 실제 경기 시작 단계에서 일반 팀과 회원 제안 팀에 같은 조건을 적용한다.

- 모임에 등록된 활성 운영진 중 코트 밖에 남을 사람이 0명이 되면 해당 팀을 보류한다. 콕 확인 기능이 켜져 있으면 미확인 등록자는 현장 운영진으로 세지 않는다. 운동 휴식 상태인 운영진은 운영할 수 있는 것으로 본다.
- 출전 가능한 다른 완성 팀이 있으면 그 팀을 다음 경기로 안내한다. 일반 팀은 기존 확정 시각(없으면 생성 시각), 회원 제안은 제출 시각을 기준으로 비교한다. 보류할 때 시각을 다시 쓰지 않으므로 교대자가 돌아오면 원래 순서가 복구된다.
- 대체 팀이 없으면 **교대까지 대기 / 이번 경기 시작**을 운영진이 선택한다. 현장 운영진이 한 명뿐인 경우에도 예외 선택을 제공한다. 새로운 경기를 자동으로 시작하지는 않는다.
- 확인 후 명단이나 대체 팀이 바뀌면 다시 판정한다. 예외 동의는 그 명단의 한 차례 출전에만 사용한다. 같은 기기의 진행 중인 배정 요청도 이미 출전하는 것으로 계산한다.
- 이미 모든 운영진이 경기 중인 경우 일반 회원 팀을 추가로 막지 않는다. 아직 묶이지 않은 자유 대기자들은 완성된 대체 팀으로 계산하지 않는다.
- `assign_match_with_admin_coverage`, `start_match_proposal_with_admin_coverage`는 세션 편집 잠금 안에서 현재 DB의 코트와 운영진을 다시 확인한다. 두 코트 시작 요청이 이어져도 두 번째 요청은 바뀐 상태를 검사한다. 기존 RPC는 구버전 호환용으로 남으므로 이 정책을 사용하려면 새 클라이언트로 갱신해야 한다.
- 실제 현장 이탈이나 운영 불가능 상태가 기록되어 있지 않으면 감지할 수 없다. 이 정책은 상시 운영진 잔류를 예외 없이 강제하는 정책이 아니다.

관련 코드: `src/lib/board/adminCoverage.ts`, `adminCoverageGate.ts`, `src/store/adminCoverageStore.ts`, `src/components/board/AdminCoverageNotice.tsx`.
