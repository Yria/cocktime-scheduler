# 코트 배치 기반 팀 생성·운영 화면 기획안

작성일: 2026-09-21 · 상태: 제안 · 적용 대상: 장소별 코트 배치 설정, 세션 설정, 팀 생성/코트 현황 화면

시각 기획서: [직접 조작하는 HTML](court-board-proposal.html) · [4쪽 PDF](court-board-proposal.pdf). 장소와 선수는 설명용 예시이며, HTML의 자동 편성은 예시 명단으로 흐름을 보여준다. 실제 세션과 연결되지 않는다.

## 1. 기획 방향

**실제 체육관과 같은 위치에 코트를 고정하고, 빈 코트에는 다음 그룹을 자동으로 준비한다. 운영진은 해당 코트에서 `완료 → 시작`으로 경기를 이어간다.**

사용자 요청을 다음과 같이 반영한다.

| 요청 | 새 동작 |
| --- | --- |
| 좌하단 `+` 버튼 제거 | 별도의 새 그룹 생성 없이 코트마다 4인 그룹 자리가 항상 존재한다. 수정은 해당 코트의 `선수 변경`에서 한다. |
| 실제 코트 배치로 표시 | 코트 수와 배치 설정에 따라 번호·위치가 고정된 코트 지도를 표시한다. 완료·시작·새로고침으로 위치가 바뀌지 않는다. |
| 장소마다 직접 배치해 저장 | 현재 그룹 카드 정도 크기의 코트를 설정 화면에서 드래그해 놓고 실제 화면을 미리 본다. 같은 장소의 다음 모임에는 저장된 배치를 불러온다. |
| 빈자리에 계속 자동 생성 | 세션 시작과 경기 완료 등으로 빈 코트가 생기면, 출전 가능한 4명을 자동 편성해 `시작 대기`로 넣는다. |

여기서 **그룹은 한 경기에 참여하는 4명**, A/B팀은 각각 2명이다. 코트의 빈 틀은 항상 보이지만, 유효한 4명이 확보되기 전에는 완성된 그룹으로 취급하지 않는다. 경기 시작은 운영진이 누른다.

## 2. 현재 구조에서 바뀌는 점

코드를 확인한 현재 흐름은 다음과 같다.

- 좌하단 `+`가 추천 모달을 열고 새 예비팀을 만든다.
- 예비팀에는 코트 연결 정보가 없다. 시작할 때 첫 빈 코트를 찾아 배정한다.
- 경기 시작 시 코트 카드가 예비팀의 화면 위치를 물려받는다.
- 경기 완료 시 예약 합류를 처리하고 보드를 전체 재정렬한다.
- 현재 자동편성은 필요하면 경기 중인 선수도 예약으로 포함한다.

새 화면에서는 **코트가 화면 위치와 배정의 기준**이 된다. 예를 들어 3번 코트에서 준비한 팀은 3번에서 시작한다. 경기 완료로 다른 코트나 준비된 팀이 이동하지 않는다.

선수 선발 정책은 최신 [네 명 편성 정책](TEAM_SELECTION_POLICY.md)을 기준으로 재사용한다. 9월 7일 작성된 [팀매칭 문서](TEAM_MATCHING_SPEC.md)의 과거 선발 설명과 혼동하지 않는다. 이번 제안의 주된 변경은 자동 실행 시점, 후보 자격, 코트 연결, 화면 구성이다.

## 3. 장소별 코트 배치 설정

**장소마다 기본 배치를 한 번 만들어 두고, 모임을 열 때 그 배치를 가져온다.** 코트 수 선택 아래에 배치 미리보기와 `배치 편집`을 제공한다. `장소 관리 → 코트 배치`에서도 같은 편집 화면으로 진입한다. 장소별 저장과 드래그 편집은 1차 필수 범위에 포함한다.

### 설정 순서

1. 일정에 지정된 장소를 불러온다. 장소가 없는 즉석 모임은 기존 장소를 선택하거나 이번 모임 전용 배치를 만든다.
2. 장소에 저장된 코트 배치를 표시하고, 오늘 사용할 코트를 선택한다. 사용 코트 수는 선택한 개수와 일치시킨다.
3. 첫 설정이면 1~8면의 코트 수를 정하고 기본 배치를 생성한다. 기존처럼 코트 수를 먼저 정한 경우에도 사용할 실제 코트를 연결한다.
4. `배치 편집`에서 코트를 직접 드래그해 실제 체육관과 같은 상대 위치에 놓는다.
5. `운영 화면 미리보기`로 결과를 확인한 뒤 저장한다. 세션을 시작하면 저장한 배치에 그룹이 자동으로 준비된다.

코트 수만으로 실제 체육관 배치를 알 수 없으므로, `가로 한 줄 / 세로 한 줄 / 두 줄`은 빠르게 초안을 만드는 도구로 제공한다. 프리셋을 적용한 뒤에도 간격을 벌리거나 줄을 어긋나게 하는 등 자유롭게 이동할 수 있다. 기존 배치 위에 프리셋을 적용했을 때는 `되돌리기`로 복구할 수 있다.

### 배치 편집 화면

```text
뒤로             코트 배치             저장
장소: ○○체육관             등록 코트 4면

[한 줄] [두 줄]      [되돌리기] [전체 보기]
코트를 끌어 실제 위치에 놓아 주세요

┌────────────────────────────────────┐
│                입구                │
│   ┌──────────┐    ┌──────────┐      │
│   │ 1번 코트 │    │ 2번 코트 │      │
│   │ ──네트── │    │ ──네트── │      │
│   └──────────┘    └──────────┘      │
│                                    │
│       ┌──────────┐  ┌──────────┐    │
│       │ 3번 코트 │  │ 4번 코트 │    │
│       │ ──네트── │  │ ──네트── │    │
│       └──────────┘  └──────────┘    │
└────────────────────────────────────┘

선택한 코트: 3번   [번호 변경] [90° 회전]
[오늘 사용 ✓]                  [위치 조정]

[운영 화면 미리보기]
저장 범위: ● 이번 모임  ○ 장소 기본 + 이번 모임
```

위 그림은 기능 배치를 설명한 와이어프레임이다. 편집 영역의 코트는 **현재 기본 그룹 카드와 비슷한 크기**를 기준으로 그린다. 실제 선수 대신 4개의 자리와 네트를 표시해 운영 화면에서 차지할 면적을 예상할 수 있게 한다.

- **이동:** 코트의 번호 영역을 잡고 드래그하면 코트 전체가 이동한다. 격자 맞춤과 옆 코트 정렬선을 제공해 위치를 쉽게 맞춘다.
- **겹침 방지:** 겹치는 위치는 드래그 중 강조하고, 놓을 때 마지막 유효 위치로 되돌린다. 주변 코트가 자동으로 밀리지는 않는다.
- **크기와 방향:** 모든 코트는 공통 기본 크기를 사용한다. 1차에는 개별 크기 조절 없이 이동·90° 회전·번호 변경을 제공한다. 회전해도 번호와 선수 이름은 똑바로 읽히게 한다.
- **번호:** 실제 코트 번호를 지정한다. 2·3·5·6번처럼 연속되지 않아도 된다. 같은 장소 배치 내 번호 중복은 저장 전에 알려준다.
- **입구:** 기준이 될 입구 표식을 옮기거나 방향을 지정할 수 있다. 모든 운영 기기에 같은 방향을 공유한다.
- **편집 영역:** 코트를 바깥쪽으로 이동하면 작업 영역을 확장한다. 빈 바닥 드래그는 화면 이동, 확대·축소는 보기 배율 변경이다. `전체 보기`는 코트 위치를 유지한 채 화면만 맞춘다.
- **드래그 대안:** 코트 선택 후 `위치 조정`의 방향 버튼이나 키보드로도 이동할 수 있다. 번호·회전·이동 버튼은 최소 44px 터치 영역을 확보한다.
- **임시 편집:** 저장 전까지는 편집 초안이다. 미리보기에서 돌아와도 초안을 유지하며, `취소`하면 기존 배치를 유지한다.

### 운영 화면 미리보기

- 편집 화면에서 `운영 화면 미리보기`를 누르면 같은 배치에 예시 선수와 `경기 중 / 시작 대기 / 인원 대기` 상태를 넣어 보여준다. 예시임을 표시한다.
- 실제 운영 화면과 같은 코트 도형, 크기, 간격, 화면 맞춤 규칙, 선택 코트 상세 영역을 사용한다. 별도의 이미지로 결과를 흉내 내지 않는다.
- 작은 휴대폰·현재 화면 크기를 바꾸어 보면서 이름과 버튼이 어디에 나타나는지 확인할 수 있다.
- 미리보기의 `완료 / 시작`은 예시 상태만 바꾸며 실제 경기나 선수 데이터를 저장하지 않는다.
- 기본 크기 보기에서는 현재 그룹 정도의 크기를 유지한다. 전체 보기에서는 배치 전체를 같은 비율로 축소하고, 작은 이름·버튼은 아래 상세 영역에서 확인한다.

### 장소 기본 배치와 이번 모임의 구분

| 저장 대상 | 적용 범위 |
| --- | --- |
| 장소 기본 배치 | 해당 장소에서 앞으로 새로 여는 모임의 초기 배치. 기존 진행 중인 모임에는 자동 전파하지 않는다. |
| 이번 모임 배치 | 현재 모임의 코트 위치·번호·오늘 사용할 코트. 해당 모임의 접속 기기에 공유한다. |
| 장소 기본 + 이번 모임 | 세션 설정에서 기본 배치를 함께 수정할 때 선택한다. 현재 모임과 앞으로의 기본값을 함께 저장한다. 다른 진행 중 모임은 유지한다. |

- 장소 관리에서는 장소 기본 배치를 저장한다. 세션 설정에서는 기본 배치를 복사해 사용하며, 수정 시 저장 범위의 기본값은 `이번 모임`이다. 처음 장소 배치를 등록할 때는 기본 배치 저장을 선택할 수 있게 안내한다.
- 장소가 없는 모임은 `이번 모임`만 제공한다. 같은 이름의 장소를 임의로 묶지 않고 등록된 장소 ID로 구분한다.
- 장소에 6면이 있고 오늘 2·3·5·6번만 사용하면, 선택한 코트의 번호·간격·상대 위치를 그대로 유지한다. 미사용 코트는 옅은 윤곽으로 남겨 위치 기준으로 삼고 자동 편성 대상에서는 제외한다.
- 장소에 등록된 코트 수와 오늘 사용할 수를 구분한다. 오늘 사용 해제가 장소의 코트를 삭제하는 동작이 되지 않게 한다.
- 모임 시작 후 위치만 수정하면 같은 코트의 경기·그룹은 유지한 채 저장된 위치를 반영한다. 사용 해제는 경기 중이면 완료 후 적용하고, 준비 중이면 해당 선수를 대기로 돌리는 결과를 안내한다.
- 운영 화면의 위치 변경은 `설정 → 코트 배치`에서만 한다. 저장 전 초안은 다른 기기에 노출하지 않고 저장 성공 후 한 번에 반영한다.

## 4. 운영 화면

### 화면 구성

```text
뒤로       코트 현황              설정
경기 중 3 · 시작 대기 1 · 대기 8명

              입구
  ┌────────────┐  ┌────────────┐
  │ 1번 경기 중 │  │ 2번 경기 중 │
  │  A팀 2명    │  │  A팀 2명    │
  │ ─── 네트 ── │  │ ─── 네트 ── │
  │  B팀 2명    │  │  B팀 2명    │
  └────────────┘  └────────────┘
  ┌────────────┐  ┌────────────┐
  │ 3번 시작대기│  │ 4번 경기 중 │
  │  A팀 2명    │  │  A팀 2명    │
  │ ─── 네트 ── │  │ ─── 네트 ── │
  │  B팀 2명    │  │  B팀 2명    │
  └────────────┘  └────────────┘

선택: 3번 코트 · 시작 대기
민수 · 지훈  vs  서연 · 유진
[선수 변경]                  [시작]

[대기 8명] [휴식 2명] [예약·제안]
```

위 배치는 설명용 2×2 예시다. 실제 화면은 장소 기본 배치를 바탕으로 이번 모임에 저장한 위치·간격·방향을 그대로 사용한다.

- 각 코트를 외곽선·서비스 라인·중앙 네트로 표현한다. 선은 옅게, 코트 번호·상태·선수 이름은 선명하게 표시한다.
- 코트를 누르면 아래의 고정된 상세 영역에 전체 이름, A/B팀, 주요 동작을 표시한다. 넓은 화면에서는 코트 내부에도 이름과 동작을 제공할 수 있다.
- 경기 중인 코트는 `완료`, 준비된 코트는 `시작`을 주요 버튼으로 제공한다. 보조 동작은 `선수 변경`과 더보기로 분리한다.
- 그룹을 준비할 때 A/B팀도 계산해 보여주고 저장한다. `시작` 시 미리 본 페어가 바뀌지 않는다. 명단 변경 시에만 다시 계산한다.
- 완료한 코트는 선택 상태를 유지한다. 자동 편성이 끝나면 같은 상세 영역의 버튼이 `시작`으로 바뀐다.
- 완료 내역은 로그에 남기고 지도에는 다음 경기 상태를 표시한다. `3번 경기 완료 · 다음 그룹 준비됨`을 짧게 안내한다.
- 좌하단 `+`는 제거한다. 고정 배치에서는 전체 `정렬` 버튼도 필요 없으므로 제거하고, 대기 인원은 하단 목록에서 확인한다.
- 대기 인원 수에는 어느 코트나 수동 예약에도 배정되지 않은 출전 가능 선수만 센다. 휴식·콕 미확인·예약 인원은 별도로 구분한다. 선수 검색은 유지한다.

### 모바일에서 위치를 유지하는 방법

실제 가로 4면을 휴대폰에서 임의로 2×2로 재배치하면 현장 위치를 찾기 어려워진다. **화면 폭이 줄어도 코트 간 앞뒤·좌우 관계는 유지한다.**

- 좁은 화면의 지도에는 코트 번호·상태를 우선 표시하고, 이름과 버튼은 선택 코트 상세 영역에 표시한다.
- 4~8면에서도 지도는 한 화면 폭에 들어오도록 맞춘다. 칸이 작아질수록 정보를 줄이며, 이름을 지나치게 축소하지 않는다.
- 기본 코트 크기는 현재 그룹 카드 정도로 유지하며, 전체 보기의 축소는 표시 배율에만 적용한다. 화면 폭 때문에 저장한 좌표·간격·방향을 다시 배열하지 않는다. 편집 화면의 미리보기에도 같은 규칙을 적용한다.
- 한 줄 7~8면처럼 지도 각 칸에 44px 선택 영역을 확보할 수 없으면 지도는 위치·상태 표시용으로 두고, 상세 영역 위에 충분한 크기의 코트 번호 선택 버튼을 제공한다. 번호 버튼은 줄바꿈할 수 있지만 지도 배치는 유지한다.
- 좁고 세로로 긴 배치는 페이지의 세로 스크롤을 허용한다. 가로 스크롤이나 확대를 해야만 `완료`할 수 있는 구조는 피한다.
- 모든 코트 선택 영역과 주요 버튼은 최소 44px 터치 영역을 확보한다. 선택 상세 영역이 대기 목록을 가리지 않도록 공간을 확보한다.
- 상태는 색과 함께 `경기 중 / 시작 대기 / 인원 대기 / 일시 정지` 문구로 표현한다. 선택 테두리와 키보드 포커스를 제공하고, 동적 변경을 읽기 보조 기능에도 알린다.

## 5. 코트 상태와 기본 흐름

| 상태 | 표시 내용 | 주요 동작 |
| --- | --- | --- |
| 인원 대기 | 빈 4인 틀과 부족 사유. 예: `출전 가능 3명 · 1명 더 필요` | 선수 변경 |
| 편성 중 | 기존 코트 틀을 유지하며 `다음 그룹 준비 중` 표시 | 처리 완료까지 시작 비활성 |
| 시작 대기 | 유효한 선수 4명, A/B팀 | 시작 |
| 경기 중 | 현재 선수 4명, 경기 경과 시간 | 완료 |
| 일시 정지 | `자동 편성 일시 정지` | 재개 |
| 재시도 필요 | `경기는 완료됐지만 다음 그룹을 준비하지 못했어요` | 다시 준비 |

정상 흐름은 `인원 대기 → 자동 편성 → 시작 대기 → 시작 → 경기 중 → 완료 → 자동 편성`이다. 인원이 없더라도 코트 틀은 없어지지 않는다.

### 사용자 예시: 1~4번 경기 중, 3번 완료

1. 운영진이 지도에서 3번을 선택하고 `완료`를 누른다.
2. 완료 저장에 성공하면 경기 기록·판수·대기시간을 갱신하고, 기존 수동 예약자의 합류도 반영한다.
3. 3번 코트의 같은 위치에 다음 출전 가능한 그룹을 자동 배정한다.
4. 다른 코트와 이미 준비된 그룹은 그대로 유지한다.
5. 3번 상세 영역에 다음 선수와 `시작`이 표시된다. 운영진이 시작을 누르면 그 코트에서 경기를 진행한다.

다음 그룹 선택·자동편성·매칭확정·코트 배정 버튼을 차례로 누르는 절차는 생략한다. 정상적인 다음 경기 준비에는 `완료` 후 추가 조작이 필요 없다.

## 6. 빈 코트 자동 편성 규칙

### 언제 실행하는가

- 세션 시작 후 참가자·코트·기존 예약을 모두 불러왔을 때.
- 경기 완료가 성공했을 때.
- 선수 추가, 콕 확인, 휴식 복귀 등으로 출전 가능한 사람이 늘었을 때.
- 준비 그룹에서 선수 이탈·휴식·자격 변경이 발생했을 때.
- 코트 추가, 일시 정지 해제, 수동 예약 취소로 빈 코트나 가용 인원이 생겼을 때.
- 재접속·편집권 이양 후 최신 상태에서 미처리된 빈 코트를 발견했을 때.

단순 화면 렌더링이나 시간 경과마다 팀을 다시 뽑지 않는다. 세션 종료 처리에서는 자동 편성을 먼저 중지한다.

### 누구를 채우는가

**자동으로 빈 코트를 채우는 경로에서는 지금 출전 가능한 선수만 사용한다.** 경기 중인 선수를 미리 예약해 `시작`할 수 없는 그룹을 만드는 기존 자동편성과 구분한다.

- 포함: 대기 상태이며 콕 확인 등 참여 조건을 충족한 선수.
- 제외: 경기 중, 휴식, 필요한 콕 확인 미완료, 다른 코트의 준비 그룹에 배정된 선수, 운영진이 확정한 수동 예약에 소속된 선수.
- 4명 선발의 성별 구성·판수·중복·실력·대기시간 정책은 현행 선택 함수를 사용한다. 단, 위 제외 조건을 먼저 적용한다.
- 막 경기를 끝낸 선수는 최신 판수와 초기화된 대기시간으로 비교한다. 같은 조합 반복을 줄이는 현행 기준을 적용하되, 교체 가능한 사람이 없을 때 연속 출전을 일괄 금지하지 않는다.
- 출전 가능한 사람이 4명 이상이어도 허용 조합을 만들 수 없으면 `현재 인원으로 편성 가능한 조합이 없어요`를 표시한다. 인원 부족과 구분한다.

### 몇 개를 만드는가

- 자동 준비 그룹은 **빈 활성 코트마다 최대 1개**다. 모든 코트가 경기 중이면 추가 자동 예비팀을 쌓지 않고 나머지는 대기로 둔다.
- 여러 빈 코트를 채울 때는 먼저 비게 된 코트부터 처리한다. 최초 진입처럼 시각이 같으면 저장된 코트 순서를 사용한다.
- 먼저 선택한 4명은 즉시 후보에서 제외해 다음 코트를 채운다. 남은 인원으로 가능한 경기 수를 고려하는 현행 선택 기준을 유지한다.
- 대기자 12명과 빈 코트 4면이면 유효 조합이 가능한 경우 3개만 준비하고, 마지막 코트는 빈 틀로 남긴다.
- 자동 편성은 4명이 완성될 때 배정한다. 3명을 여러 코트에 나눠 붙들어 두지 않는다. 운영진이 직접 선택한 일부 선수는 예외적으로 고정할 수 있다.

### 준비한 팀은 언제 바뀌는가

- 4명이 준비되면 그 명단은 유지한다. 다른 코트 완료나 늦참 때문에 자동으로 전면 재편성하지 않는다.
- 구성원 이탈·휴식으로 빈자리가 생기면 남은 선수를 유지하고 보충한다. 그 멤버로 유효 조합을 만들 수 없으면 사유와 `선수 변경`을 표시한다.
- 운영진이 `선수 변경`을 열면 해당 코트의 자동 변경을 잠시 보류한다. 저장 시 최신 참가 상태를 검증하고, 취소하면 기존 구성을 유지한다.
- 코트를 비워 두고 싶으면 `일시 정지`를 사용한다. 준비 그룹은 대기로 돌리고 해당 코트의 자동 채우기를 중지한다. 경기 중에는 현재 경기를 유지하고 `이 경기 후 정지`로 적용한다.

## 7. 기존 수동 구성·예약·회원 제안과의 관계

자동 편성 도입이 기존에 약속한 그룹을 무시하거나, 실제 경기가 가능한 코트를 예약 대기 상태로 막지 않도록 한다.

- 기본 수동 편집은 코트의 `선수 변경`에서 수행한다. 전역 `+`를 다른 위치에 다시 만들지 않는다.
- 경기 중인 사람을 기다리는 수동 예약과 다음 경기 약속은 하단 `예약·제안` 영역에서 관리한다. 이 그룹은 준비되기 전까지 특정 빈 코트를 점유하지 않는다.
- 운영진이 확정했고 전원 출전 가능해진 예약 그룹이 있으면, 빈 코트에는 해당 그룹을 확정 시각 순으로 우선 넣는다. 그런 그룹이 없으면 새로 자동 편성한다.
- 예약이 준비되더라도 이미 코트에 준비된 그룹을 밀어내지 않는다. 다음 빈 코트를 기다린다.
- 미승인 회원 제안은 코트나 선수를 자동으로 확보하지 않는다. 승인 시 선수의 최신 가용 상태를 다시 검사한다. 기존 제안의 공개 범위도 유지한다.
- 회원 제안 생성은 하단 해당 화면으로 옮기며, 코트 지도 위의 자유 배치와 분리한다.
- 기존 운영진 교대 검사는 `시작` 시 유지한다. 보류되는 경우 `운영진 교대 대기` 사유와 현재 정책의 선택지를 보여준다. 정상 시작 흐름에 일괄 확인 팝업을 추가하지 않는다.

## 8. 실패·동시 조작·복구

| 상황 | 동작 |
| --- | --- |
| 완료 저장 실패 | 현재 경기를 유지하고 완료 재시도를 제공한다. 선수를 대기로 풀거나 다음 팀을 생성하지 않는다. |
| 완료 성공, 다음 편성 실패 | 완료 기록은 유지한다. 빈 코트에 실패 사유와 `다시 준비`를 표시한다. |
| 완료 연속 탭·이벤트 재수신 | 동일 경기를 한 번만 완료하고, 해당 코트의 다음 그룹도 하나만 생성한다. |
| 두 코트가 거의 동시에 완료 | 최신 공통 후보를 기준으로 순서대로 배정하며 동일 선수를 중복 배정하지 않는다. |
| 시작 저장 실패 | 준비 그룹을 유지하고 서버 상태 확인 후 재시도한다. |
| 새로고침·다른 기기 접속 | 코트 배치, 준비 명단, A/B팀, 정지 상태를 동일하게 복원한다. 재추첨하지 않는다. |
| 편집권 상실·네트워크 단절 | 해당 기기의 자동 저장·시작·완료를 중지한다. 재연결·권한 획득 후 최신 상태부터 복구한다. |
| 세션 종료 | 새 그룹 생성을 중지한 뒤 기존 종료 절차를 처리한다. 준비 그룹을 경기 이력으로 집계하지 않는다. |

1차 실행 주체는 기존 편집권을 보유한 운영진 기기로 둔다. 조회 기기는 공유된 결과만 표시한다. 편집 기기가 모두 닫혀 있으면 새 자동 편성도 멈추며, 다음 편집권 획득 시 빈 코트를 채운다. 화면 밖에서도 계속 편성하는 서버 실행기는 후속 범위다.

완료 후 빠른 복구를 위해 `완료 취소`도 검토한다. 제공하려면 다음 경기 시작 전이며 관련 선수·예약이 다른 곳에서 변경되지 않았는지 검증하고, 완료 기록·판수·이력·다음 준비 그룹을 함께 되돌려야 한다. 단순 화면 복원으로 처리하지 않으며 1차 필수 범위에서는 제외한다.

## 9. 구현에 필요한 구조 변경

이 절은 구현 검토용이며 제품 화면에 노출하지 않는다.

- **배치 저장:** 장소 ID에 연결된 기본 배치와 세션에 복사한 배치를 따로 영속화한다. 장소 배치에는 안정적인 코트 식별자, 표시 번호, 위치, 90° 단위 방향, 입구, 작업 영역 크기, 버전을 저장한다. 세션에는 실제 경기 코트 ID와의 연결, 오늘 사용 여부, 정지 상태를 함께 저장한다. 번호를 바꿔도 다른 경기로 연결되지 않아야 한다.
- **공통 좌표와 렌더링:** 기기 픽셀 대신 공통 보드 좌표를 저장하고, 편집·미리보기·운영 화면이 같은 도형과 화면 변환을 사용한다. 현재 그룹의 기본 경계는 보드 좌표 약 158×218(`TEAM_W`, `TEAM_BOX_ABOVE + TEAM_BOX_BELOW`)이므로 이를 초기 크기 기준으로 삼고 실제 가독성을 검증한다. 확대 상태의 드래그도 좌표를 역변환해 저장한다.
- **편집과 동시 저장:** 편집 초안은 저장 전까지 로컬에 두고, 장소 기본과 세션 배치의 저장 권한·버전을 각각 검증한다. 기존 세션의 배치 변경에는 현재 편집권도 검사한다. 오래된 초안으로 다른 운영진의 저장을 조용히 덮어쓰지 않는다. `장소 기본 + 이번 모임` 저장은 둘 다 성공해야 완료로 표시한다.
- **코트별 준비 상태:** 기존 `DraftTeam`과 별개로 코트와 준비 그룹의 연결을 영속화한다. 코트 틀은 `courts`로 그리므로, 기존의 ‘2명 미만 예비팀 해체’ 규칙이 빈 코트 표시를 없애지 않는다.
- **정확한 코트 시작:** `startMatch`가 첫 빈 코트를 찾는 대신 사용자가 선택한 코트 ID를 전달하도록 바꾼다. 준비 시 저장한 A/B팀을 그대로 시작한다.
- **완료 결과 확인:** 현재 `handleComplete`의 결과를 호출부가 명시적으로 판별할 수 있게 하고, 완료 성공 및 최신 선수·이력 반영 이후 자동 채우기를 호출한다.
- **공통 조정 함수:** 화면마다 자동 생성 효과를 붙이지 않고 세션 내 단일 처리 흐름에서 빈 코트를 채운다. 자기 저장으로 생긴 알림은 추가 생성 사유가 되지 않게 한다.
- **서버 검증:** 준비 배정 저장은 최신 버전, 편집권, 코트 상태, 선수 중복을 함께 검사한다. 경기 시작·완료도 서버 검증을 유지한다. 버전 충돌 시 최신 상태를 읽어 미처리 코트만 다시 계산한다.
- **기존 세션 전환:** 진행 중 경기는 코트 ID 그대로 유지한다. 기존 미배정 예비팀·예약은 `예약·제안` 영역으로 옮기고 준비 가능한 확정 그룹부터 빈 코트에 연결한다. 초기 데이터 로드 전에 새 팀을 만들지 않는다.
- **구버전 대응:** 새 코트 연결을 모르는 클라이언트의 편집을 허용하지 않고 갱신을 안내한다. 구버전 저장이 새 준비 정보를 지우지 않도록 서버에서 형식을 검증한다.

## 10. 적용 범위와 완료 기준

### 1차 필수 범위

- `+` 및 전체 정렬 버튼 제거, 고정 코트 지도, 모바일 선택 코트 상세 영역.
- 장소별 1~8면 기본 배치 저장·불러오기, 그룹 카드 크기의 코트 드래그 편집·회전·번호 지정·입구 표시.
- 실제 운영 화면 미리보기, 장소 기본과 세션 배치 분리, 오늘 사용할 코트 선택, 모든 활성 코트의 빈 그룹 틀 표시.
- 최초 진입·완료·참여 가능 인원 변경 시 자동 편성, 코트 지정 시작.
- 준비 그룹 유지, 선수 변경, 코트 일시 정지, 기존 예약·제안 연결.
- 편집권·실패·중복 방지·재접속 복구 및 구버전 편집 차단.

### 후속 범위

벽·기둥·통로 등 건물 요소 그리기, 코트별 개별 크기 조절, 장소당 여러 배치 프리셋, 안전한 완료 취소, 편집 기기 접속과 무관한 서버 자동 편성. 코트의 자유 위치 편집과 장소별 기본 배치는 1차에 제공한다. 3D 코트나 득점·승패 기능은 이 기획에 포함하지 않는다.

### 검증 시나리오

1. 빈 코트 4면과 유효한 대기자 16명이면 생성 버튼 없이 4개 그룹이 준비된다.
2. 1~4번 경기 중 3번 완료 시, 3번 위치에만 다음 그룹이 들어가고 `시작`할 수 있다.
3. 참가자가 부족하거나 유효 조합이 없으면 코트 틀과 정확한 사유가 표시된다.
4. 두 코트의 동시 완료·연속 탭·재연결에도 경기 이력과 선수 배정이 중복되지 않는다.
5. 새로고침·다른 기기 조회 시 코트 번호·공간 관계·준비 명단·A/B팀이 동일하다.
6. 선수 이탈·휴식·복귀가 발생해도 관계없는 준비 그룹과 코트 위치는 유지된다.
7. 수동 예약은 준비 전 코트를 막지 않고, 준비 후 다음 빈 코트에서 우선 배정된다.
8. 일시 정지한 코트 및 종료 중인 세션에는 새 그룹이 생성되지 않는다.
9. 작은 휴대폰에서 가로 4면·2×4 배치를 보더라도 코트 선택과 `완료 → 시작`을 확대 없이 수행할 수 있다.
10. 자동 편성 실패 후 재시도와 편집권 이양이 완료된 경기를 되살리거나 기존 그룹을 재추첨하지 않는다.
11. 장소 A와 B에 서로 다른 배치를 저장하면 장소 선택 시 해당 배치가 불러와지며, 다시 방문해도 좌표·번호·회전·입구가 복원된다.
12. 확대 상태에서 코트를 옮긴 뒤 미리보기·저장·운영 화면을 전환해도 위치가 어긋나지 않는다. 좁은 화면에서도 같은 공간 관계가 유지된다.
13. 6면 중 2·3·5·6번만 사용하면 실제 번호와 위치를 유지하고 해당 4면에만 그룹을 자동 편성한다.
14. 장소 기본 배치를 수정해도 이미 시작한 다른 모임은 그대로이며, `이번 모임`만 수정하면 장소 기본값은 유지된다.
15. 배치 편집 취소·겹친 위치 드롭·동시 저장 충돌·미리보기 조작이 실제 진행 경기와 기존 저장 배치를 잘못 변경하지 않는다.

검증의 핵심 지표는 **완료 후 다음 그룹을 준비하는 추가 조작 0회**, **경기 전환으로 인한 코트 위치 변경 0회**, **선수 중복 배정 0건**이다.
