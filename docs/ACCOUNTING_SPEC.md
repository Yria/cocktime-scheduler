# 회비·대관비 회계 — 통합 기획서 (as-intended)

> 이 문서가 **현재 회계 기능의 단일 기준(source of truth)** 이다.
> 초기 설계 `ACCOUNTING_DESIGN.md`는 이력용으로만 둔다(내용이 낡음 — 이 문서가 우선).
> 서비스 초기(2026-07)에 기획이 수시로 바뀌며 임시 구현·수동 DB 조작이 누적되어, 이 문서로 재정비한다.
> 최종수정 2026-07-14 · 브랜치 `sam/accounting`.

---

## 0. 대전제

1. **통장 전용.** 모든 수입/지출은 은행 계좌(토스뱅크) 거래로만 발생한다. 현금 수납 케이스는 없다.
   → "현황판에서 회원 눌러 현금 수납" 같은 기능은 두지 않는다. 정산은 **입금확인**에서 은행 거래를 매칭해서만 한다.
2. **은행 거래는 메일로 수집.** 토스 거래내역 xlsx가 Gmail로 오고, 이를 읽어 파싱·적재한다(멱등).
3. **운영진(role=admin)은 회비·대관비 전부 면제.** 부과 대상에서 제외.
4. **게스트(is_guest)**: 회비 없음. 대관비만. 데려온 회원(초대자)이 대납하는 게 기본이나, 게스트 본인이 직접 입금하기도 한다.
5. **수동 DB 조작은 서비스 초기(지금)만.** 무산/커스텀 세션, 오입력 정리 등. 이후에는 시스템 플로우로만 처리한다.

## 1. 도메인 모델

### 1.1 금액
- **회비(monthly_fee)**: 5,000원/월. 회원(비운영진·비게스트) 대상. 월 단위(`period_ym`).
- **대관비(court_fee)**: **인당 정액 6,000원**(플레이스의 시간당 요금과 무관 — 시간당 요금은 지출 추정·표시용). 세션 단위(`session_id`).

### 1.2 세션이 "열렸다"의 정의
- **경기(matches)가 있으면 열린 세션.** 경기 없으면 무산 → 대관비 부과 대상 아님.
- **예외(수동 노출 플래그 `sessions.dues_include`)**: 무산/커스텀(즉석) 세션이지만 실제로 대관·정산이 필요한 경우, 실제 status는 그대로 두고 정산 화면에만 노출한다.
  → 정산상 "열린 세션" = `matches 있음 OR dues_include=true`.

### 1.3 테이블(핵심)
- `dues_charges` — 부과. `kind(monthly_fee|court_fee)`, `member_id`, `period_ym` XOR `session_id`, `amount_due`, `amount_paid`(트리거 캐시), `status(unpaid|partial|paid|overpaid|waived|void)`, `payer_hint`(게스트 대납자).
- `dues_allocations` — 입금↔부과 배분(가역). 트리거가 charge.amount_paid/status + bank_tx.status를 유지. **waived/void 부과에는 배분 금지(가드).**
- `bank_transactions` — 은행 거래. `direction(in|out)`, `amount`(양수), `balance_after`(거래 후 잔액), `category_id`(수지 분류), `session_id`(대관 지출·비회원 대관 수입을 세션에 귀속), `status(unmatched|proposed|partial|matched|ignored)`, `dedup_key`.
- `txn_categories` — 수지 분류(코트대관·콕공구·셔틀콕·기타 등). 관리자가 추가/삭제.
- `dues_settings` — 회비/대관비 기본액·계좌 등.

## 3. 화면별 기획 — 기능 요구사항 (디자인 비의존)

> 아래는 **각 화면이 무엇을 하게 해야 하는지(동작·규칙·데이터)** 만 정의한다. 레이아웃·컴포넌트·색·버튼 배치 등 **표현은 디자인 단계에서 새로 정한다**.

### 3.1 정모(메인) — 정산 상태 + 미납 추적
> 확정 디자인(§10.1): 메인은 **세션별 정산 상태**(①코트지출 연결 ②수납 완료 → 마감/미완) + **회비 진행률** + 정산함 진입. 아래 미납-추적 요구는 이 화면의 발송 기능으로 실현된다(월 순액 헤드라인 없음).
- 목적: **정산 단위(세션)가 잘 마감됐는지** + **누가 무엇을 안 냈는지** 파악·독촉.
- 미납은 **분류 단위로**: `N월 회비`(진행률 카드) / **세션별 대관비**(각 세션 카드). 완납/마감은 흐리게.
- 대관비는 **실제 낼 사람(대납 게스트 포함, payer_hint ?? member) 기준 합산**하고 게스트분 포함 여부를 알 수 있어야 한다.
- **미납 알림 발송**: **분류(그룹) 단위로만** 보낸다. 그룹 안에서 대상 회원 취사선택 가능. **전체 일괄 발송은 없앤다.** (게스트/미로그인은 푸시 불가 → 수동 안내 대상.)
- **현금 수납 기능 없음**(대전제 1) — 여기서 직접 납부 처리하지 않는다.

### 3.2 정산함(reconcile) — 은행 거래 처리 (입금+출금 모두)
- **가져오기**: Gmail에서 토스 거래내역을 수집·적재(중복 제거) + 자동 부과생성.
- **입금·출금을 한 큐에서**(날짜순 카드): **미처리**(입금·출금 함께) / **부분 처리** / **무시**. 필터(전체/입금/출금). **확인된 거래는 [회계] 원장에서 열람·취소**(정산함은 처리 전용, 저뎁스).
- **출금 1건 처리**: 카테고리 분류 + (대관료면) 어느 세션인지 지정(다른 달 세션 포함). → 세션 단위 손익에 반영(§3.3·§5). 여기서 셋팅하고, 회계는 결과·원장 표시.
- **입금 1건 처리** — 핵심 동작:
  - **납부자 지정**: 입금자명으로 후보 자동 제안 + 검색으로 선택(게스트 포함).
  - **무엇으로 처리할지 선택** — 회원 지정 시 아래 두 종류를 **함께 고를 수 있어야** 한다:
    1. **기존 미납 부과**(우선): 그 회원의 미납 회비/대관비 — **본인분 + 대납(게스트) 분**, **월 제한 없이**(다른 달 세션 대관비를 이번 달 입금으로 내는 크로스먼스 포함).
    2. **신규 생성**: 부과가 아직 없을 때 — 이번 달 회비 / 세션 대관비(커스텀·즉석 세션, 게스트 동반 시 인원 반영).
  - **금액 기반 자동선택**(기본값, 조정 가능): §4. 기존 미납 우선, 없으면 신규.
  - **확인 1회**로 처리: 기존 부과 배분 + 신규 생성·배분을 **한 트랜잭션**으로(§9-A 통합 확정 RPC).
  - **비회원(외부) 대관**: 회원 매칭이 안 되고 금액이 대관비인 경우, 회원 없이 세션에 귀속하는 수입으로 처리(`dues_confirm_court_external`).
  - **비회비/오입금**: 수입 카테고리로 분류하거나 무시.
- **부분 처리**: 입금액 일부만 배분된 거래는 완전매칭과 **구분**해 남은 금액을 추적할 수 있어야 한다("미처리 0" 완전성 보존).
- **환불 연결(신규, 스코프 포함)** — 두 케이스를 같은 메커니즘으로:
  - **차액 환불**: 초과입금(6,000 중 5,000만 회비) → 1,000 환불. / **전액 오입금 환불**: 잘못 들어온 입금 전액 환불.
  - **핵심 = 입금(IN) ↔ 환불 출금(OUT) 연결.** 환불은 실제 은행 출금 거래다.
  - 데이터: `bank_transactions.refund_of_tx_id`(OUT에, 이 출금이 환불하는 IN). 1:1(대부분). RPC `dues_link_refund(out_tx, in_tx)` + `dues_unlink_refund(out_tx)`.
  - **해결 판정**: IN의 남은 금액 = `입금액 − 배분합 − 환불합`. 0이면 완전 처리(부분에서 제거). (차액: 배분5,000+환불1,000=6,000. 오입금: 배분0+환불6,000=6,000.)
  - **연결 UX(버튼·저뎁스)**: 부분/초과 입금 카드 → "환불 연결" → **후보 출금이 버튼으로**(상대방명≈대상·금액==차액/전액·미연결·입금 이후) → 탭해 연결. 반대로 환불성 출금에서 "어느 입금?"도 가능.
  - **회계 반영**: 통장 총액(수입/지출)은 실제 현금이라 그대로(순=회비만 남음). 항목별 정산에선 연결쌍을 **환불(상쇄, wash)** 로 빼서 회비엔 5,000만, 미분류/부분엔 안 남음.
  - 엣지: 환불이 아직 통장에 없으면 "환불 예정" 표시 후 다음 가져오기 때 자동 후보. 금액 불일치(수수료 등)면 수동 지정. 한 출금이 여러 입금 환불(묶음)은 드묾 → 필요 시 링크 테이블로 확장.
- **확인됨 추적·취소**: 각 거래가 **무엇으로 처리됐는지**(회비/어느 세션 대관비/누구) 라벨로 보인다. **처리 취소는 휘발성 "방금 취소"가 아니라 확정 기록(회계 원장)에서** 한다 — 확정 거래 탭 → 처리 내역 + [취소·재처리](배분 되돌리고 입금은 미처리로 복귀). 감사 가능·의도적 취소.

### 3.3 회계(accounting) — 상세 장부 (정모 카드보다 자세)
- 그 달 **수입·지출·순**(현금흐름) + 통장 잔액.
- **분류별 순액 = 월 통장 기준(현금주의).** 항목별 순액의 **합이 반드시 "이 달 남은 돈"(=수입−지출)과 일치**한다. 그 달 통장 거래를 다음 버킷에 빠짐없이 한 번씩 담아 분해:
  - **걷은 회비**: 그 달 입금이 회비 부과에 배분된 금액(배분 기준, 부과 amount_paid 아님).
  - **세션별 대관비**: 세션별 `그 달 세션거래(비회원 입금·대관 지출) + 그 달 입금의 코트 배분분`. **그 달 통장 거래만** — 다른 달에 선지급한 대관료는 그 세션이 아니라 **지급된 달**의 회계에 잡힌다(§5). (세션 전체 손익은 정모/현황 §3.1.)
  - 그 외 카테고리(콕공구 등) 순액 — +/−가 0이면 정산 완료 파악.
  - **환불**: 그 달 환불 출금(별도 라인).
  - **미분류**: 세션·카테고리·회비 어디에도 안 붙은 잔여(미매칭 입금 + 부분배분 잔액 + 미지정 출금).
- **거래 원장**: 입출금 타임라인 + **러닝 잔액**(실제 통장과 대사). 처리된 거래 탭 → 처리 내역 + **[취소·재처리]**(정산함 미처리로 되돌림).
- **CSV 내보내기·세션별 상세 drill 없음**(세션별은 위 "세션 단위 대관비 순액"과 겹침 — 최종 결정).
- **카테고리 관리**: 추가·삭제(삭제 시 해당 거래는 미분류로).
- (출금 분류·세션 지정은 **정산함**에서 셋팅 — 여기선 결과 표시.)

### 3.4 내 회비(/my-dues) — 회원 본인 (탭 2개)
- 로그인 필수. **본인 부과 + 본인이 대납하는 게스트분만**(RLS가 관리자에겐 전체 허용 → 쿼리에 본인 필터 필수). 회원 노출 RPC는 모두 `current_member_id()` 기반 + **anon execute revoke**(로그인 열람 불변식).

**탭 ① 내 회비(/my-dues)**
- **회비 납부(액션)**: 이번 달 미납 금액 + **입금 계좌 전체번호 + 복사**(로그인 회원 전용, `dues_club_account`). 이번 달 판정은 회비의 **이월(deferred_to)을 실효 월로** 반영(이월 나간 건 제외·이월 들어온 건 포함).
- **납부 이력**: **실제 낸 것만**(미납 제외). 입금 단위로 날짜·금액·용도(`7월 회비 · 7.12 대관비`). 두 소스 = 부과 배분 입금 + `paid_by`(비부과 카테고리 납부, 콕공구 등). RPC `dues_my_payments()`.
  - **비부과 납부 귀속**: 정산함에서 입금을 카테고리로 분류할 때 **납부자 지정** → `bank_transactions.paid_by`. 그 회원 납부 이력에 표시(분류 취소 시 함께 해제).

**탭 ② 클럽 회계(/my-dues/ledger)**
- **항목별 정산만**(수입/지출) — 걷은 회비 · 세션별 대관비 순액 · 카테고리 · 환불 · 미분류 · 남은 돈. **관리자 회계(§3.3)와 동일한 월 통장 기준**이라 항목별 합 = 남은 돈으로 일치. `dues_public_ledger`.
- **월 스테퍼**: 지난달부터 한 달씩 뒤로. **당월은 정산 중이라 비공개**(오른쪽 화살표 비활성, 별도 안내 문구 없음).
- **거래 원장·정산함·개별 회원 미납은 제외**(관리자 전용).

## 4. 금액 기반 자동선택(입금확인) — 규칙

납부자(회원) 지정 시 입금액으로 기본 선택을 제안(관리자 조정 가능). **기존 미납 부과 우선**, 부족분만 신규 생성:
1. **5,000** → 회비.
2. **6,000** → 대관비 1건(본인 또는 대납 게스트분 우선, 없으면 참가 세션 신규).
3. **12,000** → 대관비 2건(본인+게스트 또는 2세션).
4. **11,000** → 회비 + 대관비 1건.
- 일반식: `amount − 5,000`이 6,000 배수면 회비 + k대관, 아니면 `amount`가 6,000 배수면 k대관. 게스트는 회비 제외.
- **완납/면제 항목은 자동선택 금지**(합계에만 넣고 배분 0 되는 오류 방지).
- 부족하면 있는 만큼만(관리자가 조정).

---

## 5. 크로스먼스 정산(대관비 선지급/후지급)

- 코트 대관비는 세션과 **다른 달에 지급**될 수 있다(예: 6/29 지급 → 7/5 세션).
- 출금을 세션에 매칭할 때 **±1개월** 세션까지 후보로(다른 달 세션에 링크 가능).
- **두 관점을 분리**한다:
  - **정모/현황(§3.1) = 세션 기준(발생주의).** 세션에 링크된 지출은 발생월과 무관하게 그 세션 순액에 포함 → "이 세션이 대관비를 회수했나" 파악.
  - **회계(§3.3) = 월 통장 기준(현금주의).** 6/29 지급분은 **6월 회계**의 그 세션 대관비 지출로 잡히고, 7월 회계엔 7월에 받은 대관 수입만 잡힌다 → 월 항목별 합이 그 달 남은 돈과 일치.
- (회원 공개 회계 §3.4도 회계와 동일한 현금주의 — 관리자 화면과 숫자가 일치.)

## 6. 알림

- `payment_confirmed` — 입금 처리 시 해당 회원(비게스트)에게.
- `dues_unpaid` — 미납 알림. **카테고리 그룹 단위 선택 발송만**(대상 회원 배열 + 커스텀 문구 `payload.msg`). **전체 일괄 발송(`dues_notify_unpaid`)은 제거**(현황판 상단 종/일괄 버튼도 제거).

## 7. 권한/보안

- 모든 쓰기는 `SECURITY DEFINER` RPC + `is_admin()` 가드. 조회는 RLS.
- `dues_charges`/`dues_allocations`는 관리자 or 본인(payer_hint 포함) 열람. **본인 화면은 쿼리에 본인 필터 필수**(관리자 계정 오노출 방지).
- 게스트는 `auth_user_id` 없어 푸시 대상 제외.

### 8.2 쿼리 최적화(중복 조회·캐싱)
- **핵심 낭비: 부모 `DuesAdminPage`가 모든 탭에서 `loadAdmin(ym)`(3쿼리)을 항상 실행** → 입금확인/수지 탭에서도 현황판 데이터(members·monthly·court)를 매번 재조회. 입금확인 탭 = 10라운드트립, 수지 탭 = 10라운드트립(2웨이브).
  → **loadAdmin은 현황판 탭에서만** 실행(다른 탭 컴포넌트 mount 시 로드하는 패턴과 통일).
- **탭 전환마다 같은 달 데이터 재조회**: `fetchBankTransactions`·`fetchCategories`·`fetchMonthSessions`·`fetchCourtCharges`·`fetchMonthlyCharges`가 여러 load에서 중복. 캐시/가드 전무(재mount마다 풀로드).
  → **ym 단위 캐시 가드**(스토어에 loadedYm 기록, 같은 ym이면 skip) + **공통 fetch 1회 공유**(월 공통 데이터를 `loadMonth(ym)` 한 번, 탭별 추가분만).
- `fetchMonthlyCharges`+`fetchCourtCharges` → `dues_charges` 한 쿼리로 병합 가능(그 달 회비+대관).
- `fetchTxAllocations`(전체 배분)·`fetchUnpaidByMember`(전월 미납) 등 전역 조회는 필요 범위로 축소 검토(단, 크로스먼스 미납은 월무관 필요 — §5).
- `loadLedger`의 순차 await(`fetchSessionTxns`는 monthSessions ids 필요)는 불가피 — 유지.

## 9. 기능 재정비에서 반드시 고칠 회귀(적대적 검증 확정)

직전 입금확인 통합 재작성이 "회원의 실제 미납 부과 매칭" 경로를 제거하고 "이 달 세션 생성"만 남겨 생긴 회귀:

- **A. 통합 확정 RPC 필요(match+compose)**: 입금확인 확정이 ①기존 미납 부과(본인+대납, 월무관) 배분 + ②신규(회비/세션) 생성·배분을 한 트랜잭션으로 처리해야 한다. 현재는 compose(생성)만 → 아래 버그.
- **B. 게스트 몫 고아(HIGH)**: 게스트는 별도 court charge(member=게스트, payer_hint=초대자)로 생성됨. 초대자 입금 처리 시 그 charge를 배분해야 하는데, 현재는 본인 charge amount_due만 인원배수로 올려 게스트 charge가 영구 미납·이중계상. → 대납 charge를 라인으로 선택·배분(§3.2 ②-1).
- **C. 크로스먼스 대관비 매칭 불가(HIGH)**: 다른 달 세션의 기존 미납 대관비를 이번 달 입금으로 못 냄(이 달 세션 칩만 노출). → 기존 미납 부과는 월무관 노출.
- **D. 완납 회비 프리셀렉트(MED)**: 완납/면제 항목 자동선택 금지(§4).
- 사이드: `duesConfirmMatch`/`fetchMemberUnpaidCharges`/`duesConfirmNewCourt`/`duesConfirmNewMonthly` 등은 재통합 후 정리.

## 10. 구현 계획 — 디자인發 기능 변경점 + 쿼리 최적화

### 10.1 확정 디자인이 부르는 기능 변경
- **화면 = 4 라우트**: `/dues/:ym`(정모·메인), `/dues/:ym/inbox`(정산함, 입출금), `/dues/:ym/ledger`(회계), `/my-dues`. (구 3탭 `status/reconcile/ledger` 폐기.)
- **정모(메인)**: 세션별 "정산 상태"(①코트지출 연결 ②수납 완료 → 마감/미완) + 회비 진행 + 정산함 진입. 월 순액 헤드라인 없음.
- **정산함**: 입금+출금 한 큐(날짜순 카드, 버튼 선택). 상단 가져오기. 입금=`dues_confirm_reconcile`, 출금=`setTxnCategory`/`setTxnSession`, 환불=`dues_link_refund`.
- **회계**: 수입/지출/남은돈 + 항목별 정산 + 거래 내역(러닝잔액)에서 취소. 쉬운 용어. CSV·세션상세 없음.
- **내 회비**: 본인 + 클럽 회계(항목별만) → 회원용 집계 RPC `dues_public_ledger(ym)`(개별 미납·원장 제외).
- **신규 RPC**: `dues_confirm_reconcile`(match+compose 통합, §9-A~D 해소), `dues_link_refund`/`unlink`, `dues_public_ledger`. **제거**: `dues_notify_unpaid`(전체 알림) 및 §8.1 사문화 wrapper.

### 10.2 쿼리 최적화 — **구현 완료 현황(2026-07)**
- **월 공통 데이터 1회 로드 + ym 캐시**: `duesStore.loadMonth(ym)`가 정모·정산함·회계 공통 데이터를 로드하고 `loadedYm`로 캐시 — 화면 전환 시 재조회 없음(같은 ym 재진입 skip). `DuesAdminPage` 셸에서 한 번 호출.
  - wave1(병렬 8): members·monthly·court·bankTxns·ledgerSessions·categories·settings·unpaidByMember. wave2(병렬 2, 앞 id 필요): `fetchSessionTxns`(monthSessions ids)·`fetchTxAllocations`(그 달 bankTxns ids로 스코프 — 전역 배분 누적 회피).
  - `monthSessions`는 `ledgerSessions`(±1개월 상위집합)에서 파생 → 세션 쿼리 1회.
- **뮤테이션 후 부분 갱신**(로딩 플래그 안 켜서 깜빡임 없음):
  - `refreshMonth(ym)` — charge를 바꾸는 확정/대사취소용(monthly·court·bankTxns·unpaid + wave2). 정적(회원·세션·카테고리·설정) 재조회 안 함.
  - `refreshTxns(ym)` — tx만 바꾸는 분류·세션지정·환불연결용(bankTxns·sessionTxns·txAllocations 3쿼리).
- **집계는 서버 RPC로**: 회원 공개 회계는 `dues_public_ledger(ym)` 단일 RPC(월 통장 기준 현금주의, §3.3과 동일 분해). 관리자 회계 항목별은 이미 로드한 `bankTxns + txAllocations`를 클라에서 분해(각 Ledger 하위 컴포넌트가 필요한 스토어 슬라이스만 구독 → 리렌더 격리).
- **"loadMonth를 단일 스냅샷 RPC로?" 판단 → 채택 보류**: 현재 병렬 fetch는 이미 캐시·부분갱신(refresh*)과 로직을 공유한다. 스냅샷 RPC로 묶으면 `refreshMonth/refreshTxns`용 개별 fetch를 **이중 유지**해야 하고(SQL+클라), 병렬이라 왕복 이득도 작다 → 유지보수 우위로 병렬 fetch 유지. (무거운 집계인 공개 회계만 RPC로.)
