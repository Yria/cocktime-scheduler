# 늦참 평균 판수 보정의 수학적 검증

> 검증일: 2026-09-07. [늦참 보정 SQL](../supabase/migrations/20260907040000_late_join_game_count.sql)과 [실제 추천 함수](../src/lib/teamSelection/recommendTeammates.ts)를 기준으로 검증했다. 운영 DB에 새 SQL을 배포하지 않았다.

평균 보정은 **늦참자의 추천용 판수를 기존 참가자의 평균 수준에 놓는 방법**으로 성립한다. 반올림 오차·반복 합류의 안정성을 증명할 수 있다. 다만 출전 횟수·대기 순서·참가 시간 대비 경기 기회를 똑같이 보장하는 방법은 아니다. 아래 일반 증명과 유한 범위 실행 검사를 구분한다.

## 1. 계산 대상과 전제

- 기존 참가자는 같은 세션의 대기/경기 중 선수다. 휴식·본인·콕 체크 ON일 때 미확인은 제외한다.
- `g_i`는 참가자 i의 **완료 판수 + 이전 보정값**이다. 실제 출전 기록만의 평균이 아니다.
- 판수는 0 이상의 정수다. 진행 중인 경기는 아직 `g_i`에 더하지 않는다.
- 아래 오차·안정성 증명은 기존 판수가 0인 신규 참가자를 대상으로 한다. 높은 기존 판수를 가진 복귀자는 `max(기존 값, 평균 보정)` 때문에 평균보다 0.5판 이상 높을 수 있다.
- 참가자가 없으면 평균 대신 0을 사용한다.

기존 참가자가 n명이고 판수 합이 S일 때:

```text
μ = S / n
r = floor(μ + 1/2)             # PostgreSQL의 비음수 반올림과 동일
신규 참가자의 추천용 판수 = r
일반 보정 = max(기존 판수, r)
```

## 2. 보장되는 성질

### 평균과의 차이는 최대 0.5판

반올림의 정의에서 `r - 1/2 ≤ μ < r + 1/2`이므로 `|r - μ| ≤ 1/2`이다. 기존 판수가 정수이므로 r은 기존 최소·최대 판수 사이에 있다. 모든 기존 참가자가 4판이면 신규 참가자도 4판이다.

현재 `W_GAME=10`이므로 반올림으로 발생하는 **판수 비용의 오차는 최대 5점**이다. 이 상한은 전체 추천 순위나 기다리는 시간의 오차 상한을 뜻하지 않는다.

### 여러 명이 들어와도 보정값이 연쇄적으로 커지지 않는다

경기 완료·이탈·휴식·설정 변경 없이, 같은 기준을 적용받는 신규 참가자 k명이 들어온다고 하자. 모두 r을 받으면 새 평균은:

```text
μ_k = (nμ + kr) / (n+k)
    = μ + k/(n+k) × (r-μ)
```

새 평균은 기존 평균 μ와 정수 r 사이에 있다. 둘은 같은 반올림 구간에 있으므로 `round(μ_k)=r`이다. 따라서 다음 신규 참가자도 r을 받으며, 귀납적으로 임의의 유한한 인원에 대해 성립한다.

전체 평균 자체의 이동은 `|μ_k-μ| = k/(n+k) × |r-μ| ≤ 0.5판`이다. **정확한 평균이 항상 그대로 유지되는 것은 아니다.** 기존 값이 `3,4`이면 평균 3.5를 반올림한 4가 계속 추가되어 전체 평균은 4에 가까워진다.

기존 판수가 높은 복귀자나 그 사이 발생한 경기 완료·인원 이탈에는 이 증명을 적용할 수 없다.

### 신규 참가자 추가만으로 보정 판수의 분산이 커지지 않는다

기존 모집단 분산을 V, 반올림 오차를 `e=r-μ`라 두면:

```text
V_k = n/(n+k) × V + nk/(n+k)² × e²
```

r은 μ에 가장 가까운 정수이므로 모든 기존 정수 판수에 대해 `e² ≤ (g_i-μ)²`, 따라서 `e² ≤ V`이다. 이를 대입하면 `V_k ≤ V`다. 이 역시 **보정된 숫자의 분산**에 관한 결과이며 실제 출전 경험이나 장기 공정성이 좋아졌다는 증명은 아니다.

### 같은 다른 조건에서는 먼저 기다린 사람이 유리하다

판수·실력·성별·유형·그룹 이력·경기 중 여부가 같은 두 대기자를 비교하면 대기 비용만 남는다. 현재 `W_WAIT=1`이므로 `w`분 먼저 기다린 기존 참가자는 합류 직후 신규 참가자보다 비용이 w점 낮다.

이는 다른 조건이 같을 때의 성질이다. 서로 다른 판수나 그룹 이력을 가진 기존 참가자 전원보다 늦참자가 뒤에 선다는 뜻은 아니다.

## 3. 보장되지 않는 성질과 확인한 반례

### 경기 완료 직전·직후 합류는 최대 1판 차이가 난다

같은 기존 참가자 n명 중 p명이 각자 현재 진행 중인 경기 한 판을 완료하면 평균 증가량은 `p/n`이다. `0 ≤ p/n ≤ 1`이므로 반올림 전후의 기준 차이는 0 또는 1판이다. 여러 경기 주기가 지난 경우나 모집단 자체가 바뀐 경우의 상한은 아니다.

기존 8명 모두 4판을 완료했고 현재 두 코트에서 경기 중인 상황을 비교한다. 아래 두 경우는 다른 조건이 같은 별도 세션이다.

| 합류 시점 | 기존 참가자의 기준 판수 | 늦참자 시작 판수 |
| --- | --- | --- |
| 두 경기 완료 직전 | 모두 4 | 4 |
| 두 경기 완료 직후 | 모두 5 | 5 |

첫 경우의 늦참자는 경기를 뛰지 않았는데 기존 참가자들이 완료한 뒤에도 4판이다. 두 경우의 출전 기회 차이는 거의 없어도 판수 비용에는 **10점 차이**가 남는다. 실제 SQL의 최초 콕 확인 경로에서 재현했다. 이는 완료된 판수만 기준으로 삼는 현재 정책의 시간 경계 효과다.

경기 중인 판을 포함하는 정책은 이 경계 문제를 줄이는 대안이지만, 평균 기준·추천 비교에서 어떤 시점에 한 판을 인정할지와 취소 처리를 함께 정해야 한다. 이번 검증에서는 정책이나 제품 코드를 변경하지 않았다.

### 평균 판수를 맞춰도 이력 차이 때문에 늦참자가 먼저 뽑힐 수 있다

현재 추천 비용에는 판수 외에 실력·대기·그룹 이력·유형 등의 항이 합산된다. 기존 참가자의 과거 이력이 신규 참가자에게 복사되지는 않는다.

같은 등급·성별이고, 대기·유형·경기 중 비용 차이가 없는 후보를 비교한다. 기존 참가자 A는 선택된 시드 S와 과거 두 경기에 함께 참여했다. 신규 참가자 B의 합류 평균은 3판이다.

| 후보 | 판수 비용 | 2명 겹침 이력 비용 | 새 만남 보너스 | 총비용 |
| --- | --- | --- | --- | --- |
| 기존 A: 2판 | 20 | 8 × 2 = 16 | 0 | 36 |
| 늦참 B: 평균 보정 3판 | 30 | 0 | -12 | 18 |

최초 검증 때 B의 비용은 30이었다. 이후 [새 만남 보정](TEAM_MIXING_VALIDATION.md)이 추가되어 현재는 S와의 첫 만남 보너스 -12를 받는다. 늦참 평균 판수 자체는 같은 3판이다.

낮은 비용이 먼저이므로 B를 뽑는다. 실제 `recommendTeammates`와 `autoFillTeammates` 모두 같은 결과를 냈다. 따라서 **‘늦참자가 더 적게 뛴 기존 참가자보다 먼저 나가지 않는다’는 규칙은 현재 모델에서 성립하지 않는다.**

참가 시간에 비례한 출전 횟수, 최대 대기시간, 연속 출전 제한도 평균 보정만으로 보장할 수 없다. 엄격한 보장이 필요하다면 해당 조건을 선발 제약으로 별도 정의해야 한다.

## 4. 실행 검사

[수학적 성질·반례 검사](../src/lib/teamSelection/lateJoinFairness.test.ts):

```sh
pnpm exec vitest run src/lib/teamSelection/lateJoinFairness.test.ts --reporter=verbose
```

7개 검사가 통과했다. 검증 내용은 다음과 같다.

| 범위 | 실행 내용 |
| --- | --- |
| 1~6명, 각 0~8판의 순서 무관 조합 5,004개 | 실제 PGlite PostgreSQL에서 신규 INSERT 보정 실행. 정확한 정수 산술로 반올림·0.5판 오차·최소/최대 범위 확인 |
| 각 조합에 신규 1~20명: 100,080개 경우 | SQL에서 얻은 최초 기준을 출발점으로 반올림 불변성·평균 이동·분산 비증가를 정수 산술로 검사 |
| 각 조합에 추가 4명 | 실제 INSERT 보정을 더 실행해 총 25,020명의 신규 판수가 최초 기준과 같은지 확인 |
| 각 조합에서 0~n명 완료 | 고정 모집단의 한 경기 주기 전후 기준 차이가 0 또는 1인지 검사 |
| 경기 종료 시점 반례 | 실제 SQL의 최초 콕 확인을 완료 전/후에 실행해 4판/5판 확인. 경기 완료에 따른 카운트 변화만 직접 적용하여 평균 효과를 분리 |
| 대기시간·그룹 이력 | 실제 추천·자동편성 함수에 동일 조건 및 반례를 넣어 비용·선택 결과 확인 |

별도의 [SQL 동작 검사](../supabase/tests/late_join_game_count.test.mjs) 11개는 ON/OFF, 미합류자 제외, 중복 확인, 복귀, 설정 전환 등을 검증한다. 기존 추천·설정 검사 52개 통과는 해당 기능의 회귀 확인이다. 이 검사 수를 전체 시스템의 수학적 공정성 증명으로 해석하면 안 된다.

유한 조합 검사는 위 일반 증명을 보조하며 임의의 규모를 전수 검사한 것은 아니다. 운영 데이터의 장기 분포, 브라우저 동기화, 별도 DB 연결 사이의 경쟁은 이번 수학 검증 범위에 포함하지 않는다.

## 5. 기획에 사용할 결론

‘늦참자는 합류 당시 기존 참가자의 평균 수준으로 추천용 판수를 보정하고, 합류 이후의 대기시간·경기 이력과 다른 편성 조건을 함께 평가한다’는 설명은 현재 수식과 일치한다.

‘늦게 와도 불리하거나 유리하지 않다’, ‘기존 참가자의 출전 순서를 침범하지 않는다’, ‘참여 시간 대비 출전 기회가 같다’는 설명은 검증되지 않았거나 위 반례로 성립하지 않는다.
