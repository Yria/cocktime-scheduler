## 화면 변경

- 현황: 회비와 대관·모임을 카드 단위로 대조한다. 완납·미납·이월 또는 제외 인원을 분리하고, 기존 참석·부과 제외 사유와 납부 근거를 유지한다. 발행되지 않은 대상을 미납으로 계산하지 않는다. 일반 정산 조작은 해당 탭으로 이동해 수행한다.
- 정산함: 원본 2b처럼 납부자 이름·변경 버튼 → 배분 막대·잔액 → 부과 선택 칩 → 전체 너비 확인 버튼 순서로 배치한다. 매칭된 입금은 카드 자체를 펼칠 필요 없이 바로 확인한다. 미매칭·동명이인은 카드 안에서 이름·년생으로 선택한다. 금액 조정·메모·대납·이월·용도 지정·환불 및 같은 입금의 다른 분할 잔액은 정산 옵션에서 기존 기능으로 연결한다. 거래 검색은 기존 기능을 유지하기 위해 상단에 남겼다.
- 회계: 월 수입·지출 요약 아래 같은 항목의 수입·지출을 한 행에서 비교한다. 금액 열을 고정하고 필터를 줄바꿈해 표시한다. 하단 전체 거래 내역과 기존 연결 해제·환불 취소 경로는 유지한다.
- 부과: 탭을 열면 즉시 종류·이름·발생일 / 명단 / 계산 방식 / 합계·발행의 기본 전표를 표시한다. `지난 명단`에서 기존 회차의 참여자·식사 명단을 가져온다. 총액 분할·인당 직접 입력과 올림 단위, 명단의 선택·제외는 로컬에서 계산한다. `N명에게 발행`으로 기본 전표를 확정한다. 개별 금액·분할 납기는 부과 옵션에서, 기존 부과 내역·회비·대관 및 이월은 하단 관리 링크에서 접근한다.

## 원본과 현재 기능의 차이

1. 원본의 통장 거래 전체에 대한 `취소됨` 상태는 현재 데이터 모델에 없다. 납부 연결 해제와 환불 취소를 각각 제공하며, 원본 통장 거래는 보존한다. 목업처럼 거래 자체에 취소선을 긋지 않았다.
2. 서버가 마지막 통장 동기화 시각을 반환하지 않는다. 이번 화면에서 가져오기와 새로고침이 성공한 시각만 표시한다.
3. 수동 JSON 백업 내보내기는 후속 사용자 요청으로 제거했다. 전환·롤백 시 자동 복구 백업은 별도 내부 경로로 유지한다.
4. 원본의 자동 배분과 회원 잔액 보관 예시는 샘플 동작이다. 앱은 기존의 확실한 단일 후보 제안과 잔액 처리 규칙을 유지한다. 남는 돈의 이월·용도 지정이 필요하면 해당 기존 기능으로 처리한다.

## 정산함 재점검 및 보정

사용자의 재점검 요청으로 원본 2b와 실제 화면을 다시 비교했다. 앞선 구현은 기존 처리 방식 버튼, 항상 보이는 회원 검색, 금액 입력·메모·대납 체크박스와 중복 확인 요약을 남겨 원본의 짧은 전표 구조를 충분히 반영하지 못했다.

- 기본 전표에서는 처리 방식 선택 행과 상세 입력을 제거하고, 배분 항목을 짧은 칩으로 표시한다. 선택된 항목은 기존 디자인 시스템의 반전 색을 사용한다.
- 납부자 이름이 카드 제목이 되고 은행 입금자명은 보조 정보로 표시된다. 변경 시 년생/ID로 동명이인을 구별하며, 선택하면 카드 안의 납부 항목으로 이어진다. 키보드 포커스는 변경 버튼으로 돌아온다.
- 세부 작업은 상단 `…`(접근명 `정산 옵션`)로 연다. 기본 납부 확인에는 모달이나 추가 확인 단계를 요구하지 않는다. 부과별 금액 수정·대납 확인·메모 및 이월/용도/환불 경로는 유지한다.
- 기존 환불 원입금 선택기의 `.ac-receipt`와 충돌하지 않도록 정산 전표 컨테이너에는 `.ac-inbox-receipt`를 사용한다. 확인 버튼이 카드 너비를 채우는지 별도로 검증한다.
- 새 DB 호출이나 회계 명령을 추가하지 않았다. 서버 검증, 납부자 재지정 제약, 중복 확정 방지, 응답 유실 재시도는 기존 흐름을 재사용한다. 운영 데이터와 과거 월 회계는 수정하지 않았다.
- 원본의 샘플 자동 배분·회원 잔액 보관을 새 금융 로직으로 옮기지 않았다. 기존의 확실한 단일 후보 제안만 자동 선택하고 나머지는 사용자가 선택한다. 회계 원장의 기존 상세 편집과 취소 기능도 유지한다.

## 부과 화면 원본 2d 반영

정산함 보정 후 사용자가 부과 화면도 같은 디자인으로 요청하여 원본 2d를 MCP 미리보기로 다시 확인했다. 기존 색상·폰트·반경·입력·칩·선택 색 토큰을 그대로 사용하고 전표 구조와 기본 진입 경로를 맞췄다.

- 첫 화면의 발행 메뉴와 별도의 `새 수동 부과` 진입 단계를 기본 전표로 바꿨다. 원본처럼 종류·이름·발생일, 선택 명단, 계산 방식과 금액, 인당 금액·합계, 전체 너비의 발행 버튼이 순서대로 이어진다.
- 참고 회차 폼은 상단 `지난 명단`에서 연다. 실제로 가져온 회차와 인원을 명단 아래 표시한다. 기존에 선택한 회원은 유지하고 중복 회원 ID는 추가하지 않는다.
- 이름·초성·년생 검색과 선택 상태는 서버 호출 없이 처리한다. 동명이인은 년생 또는 ID로 구분한다. 제외한 사람은 명단에서 지우지 않고 선택 해제·취소선으로 표시한다.
- 기본 전표의 총액·명단·올림 계산은 기존 `updateManualLines`를 재사용한다. 발행 요청도 기존 `issue` 명령과 `useInlineAccounting`의 검증·재시도 경로를 사용한다. 기본 전표는 필수 처리 사유 입력과 별도 서버 미리보기 화면을 제거하고 `N명에게 발행` 한 번으로 확정한다. 비워 둔 처리 사유에는 부과 이름·인원을 기록하며, 메모를 직접 입력할 수도 있다.
- 발행 시도 후 응답이 유실되면 입력과 다른 조작을 잠그고 동일 요청 ID로 결과만 재확인한다. 상세 부과·취소 후 발행·분할 납기 등의 기존 미리보기 흐름은 유지한다.
- 부과 옵션에는 게스트·비활성 회원, 개별 금액·납기, 처리 사유, 입력 초기화를 둔다. 기존 발행 내역·회비·대관 부과·미납 및 입금 이월은 하단 관리 링크로 연결했다. 초안은 다른 탭과 발행 내역을 다녀와도 유지한다.
- 원본의 샘플 회원·금액·발행 완료 토글은 실제 운영 사실로 사용하지 않는다. 실제 명단을 고르거나 가져오기 전에는 대상 0명이고 발행은 비활성이다. 실제 발행 후에는 완료 안내를 표시하며, 취소·복구는 기존 관리 기능에서 수행한다.
