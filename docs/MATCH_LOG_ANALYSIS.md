## 1. 데이터 접근

Supabase REST(PostgREST)로 읽기 전용 조회한다. 키는 `.env.local`의 `SUPABASE_SERVICE_ROLE_KEY`.

```bash

# 헤더 두 개 모두 필요
curl -s "$URL/matches?session_id=eq.108&status=eq.completed&order=started_at.asc" \
  -H "apikey: $KEY" -H "Authorization: Bearer $KEY"
```

핵심 테이블·필드:

| 테이블 | 분석에 쓰는 필드 |
|---|---|
| `sessions` | `id`, `court_count`, `started_at`, `ended_at`, `status`, `match_assign_count` |
| `matches` | `session_id`, `court_id`, `game_type`, `team_a_p1..team_b_p2`(session_players.id), `status`, `started_at`, `ended_at`, **`player_snapshot`**(4인 `{id,name,gender,skills:{grade}}`) |

**★ 등급은 반드시 `player_snapshot`의 "당시" 등급을 쓴다.** 사후 로스터 등급은 세션 중 변경분이 소급 적용돼 지표를 왜곡한다(실사례: 2026-07-26 김길환이 세션 후반 3→1로 변경 — 로스터 값 1을 쓰면 스프레드가 과대측정됨). `joined_at`은 세션 open 시 일괄 생성이라 실제 도착 시각이 아님에 주의.

구(舊) 데이터 참고: `pair_history` 테이블은 2026-07-27 삭제됨(마이그레이션 `20260727090000`) — 동반 이력은 완료 `matches`의 4인 구성에서 파생한다.

## 2. 표준 지표 정의

경기는 **완료(ended_at) 순** 정렬 후 계산한다.

- **overlapK / reunion4**: 각 경기의 4인 집합 vs *이전 모든 완료 경기*의 최대 교집합이 K 이상인 경기 비율. K=2/3, 4(=reunion4, 완전 재결성). overlap2 ⊇ overlap3 ⊇ reunion4.
- **pairs_met_3plus**: 3회 이상 함께 뛴 쌍 ÷ C(참가자 수, 2).
- **개인 2인 겹침**: 1인당 "2회 이상 동반한 상대 수", "동일인 최다 동반 횟수", "3회+ 동반자 보유 선수 비율".
- **avg_distinct_coplayers**: 1인당 함께 뛴 고유 인원.
- **판수 형평**: 세션 종료 시 game_count의 std·range(max−min).
- **스프레드**: 경기 4인 등급 max−min의 평균, spread≤2 경기 비율.
- **tier hard-game**: 구간 low 1-3 / mid 4-6 / high 7-10. hard = 나머지 3인 전원 등급 ≥ 본인−1. **본인 등급의 단조 함수이므로 tier 간 비교 금지** — 같은 tier의 시점 간/시나리오 간 비교만 유효.
- **노출 분포**: 동반자 등급 − 본인 등급이 ≤−2 below / ±1 mid / ≥+2 above. **절대 목표(예: 3:4:3)와 비교하지 말고, 같은 로스터의 무작위 4인 추출 기대치(random feasible) 대비로 평가** — 로스터 등급 분포(종형)가 편차의 주범이다.
- **대기**: 본인 경기 종료 → 다음 경기 시작 간격(분). 합류 전·세션 종료 후 구간 제외.

## 3. 실로그 vs 알고리즘 시뮬 비교

### 하네스 원칙
- 점수 로직을 **재구현하지 말고 `src/lib/teamSelection/*` 실제 함수를 import** 한다(tsx/bun 실행, 외부 import는 전부 type-only라 가능). 포팅 오차가 최대 리스크.
- ctx 형태: `groupHistory = {matchId, members(4인 id)}[]`, `lastGameType`, `playingIds`. 자동편성은 `autoFillTeammates(confirmed, pool, ctx, count, undefined, { maxPlaying: 1 })`.
- `Math.random`·`Date.now`를 **시드 PRNG·가상 클록으로 몽키패치**(pairPlayers 동점 랜덤·W_WAIT 분당 가중 재현에 필수).
- 운영 흐름 재현: t=0 코트 순차 채움 → 완료 즉시 그 코트 자동편성 → ghost는 본인 경기 종료 후 팀 합류 → 완료 시 gameCount+1·waitSince=now·groupHistory append. 경기 시간 분포를 명시(예: 10~15분 균등)하고 실제 평균(≈11분)과의 차이를 wallclock 해석에서 분리한다.
- 과거 하네스는 세션 스크래치패드(휘발)에 있었음 — 재구축 시 이 문서가 기준.

### ★ 함정 체크리스트 (전부 실제 감사에서 적발된 것)
1. **시드별 로스터 셔플 필수** — 정렬 고정 로스터 + stable sort 동점 타이브레이크가 특정 집단(예: 여성 먼저)에 계통 편향을 만든다. 셔플 없이는 성별/등급 효과 결론이 오염된다.
2. **우측절단 median·표본 min 인용 금지** — "60판 내 미발생"이 절반쯤이면 median이 계단식으로 튀고, min은 시드 수에 단조 감소한다. p01/p05/p25/p75/p95를 쓴다.
3. **표본 수 확인** — 비율 지표는 200시드로 부족할 수 있다(SE = sd/√n 명시, 필요 시 1000+). 소표본 셀(n<30)은 인용 금지.
4. **actual은 1회 실현치** — sim 분포의 sd 대비 z(또는 %seeds<actual)로 유의성을 표기하고, |z|<2는 tie로 판정한다.
5. **귀무기준은 조건부로** — 예: "겹친 3인의 여성 쏠림"은 로스터 성비가 아니라 *실제 경기 성별 구성* 조건부 기대치와 비교해야 한다.
6. **스냅샷 등급 사용** (§1 참조).
7. 실로그에는 **수동 개입·휴식·지연이 섞여 있다** — 대기/시간 지표는 actual이 구조적으로 유리하고, 겹침/다양성 지표는 불리함을 해석에 명시한다.

## 4c. 세션 237 (2026-08-17) — "같은 사람하고만 친다" 민원 감사

### 지표 3단 비교 — 실측 / 조건부 무작위 / 완전자동

조건부 무작위 = 실 타임라인의 코트 점유·경기별 실제 성별 구성·출석 구간을 전부 고정하고 사람만 재배치.

- 확정 수동 3건: 라벨이 남복인데 여성 1명 포함(#2·#8·#11) — 세 여성 모두 `allow_mixed_single=false`라 W_GENDER=50이 붙어 자동으로는 생성 불가.

### 몫 분해 (개인 최다동반 4.32회 기준)

구조 ≥2.76회(≥64%) / 자동편성 미채택 1.14회(개선 가능분의 73%) / 가중치 여지 0.42회(27%).
**가중치 튜닝은 세 번째 레버다.** 현 채택률에서 r16의 실현 이득은 0.02~0.08회 = 인지 불가.

### 코드 결함 (편성 반복과 직결)

1. **ghost 실효 페널티가 명목 30이 아니라 +9.4(≈1판)** — 프로덕션 점수함수 직접 호출로 재현. `complete_match`가 완료 시점에만 gc+1(−10) + `assign_match`가 `wait_since`를 안 건드려 경기 중에도 대기 보너스 누적(−10.6) + W_PLAYING(+30) = 순 +9.4. 코트 위 사람은 애초에 gc가 최저라 1판 페널티를 안고도 상위 → 연속 출전.
2. **`W_GROUP4 > 최대 스프레드 확장 벌점` 불변식이 이미 깨져 있다.** 주석·`TEAM_GENERATION_RULES.md` §35·테스트가 k=6(=54)을 최대로 가정하나 `SkillGrade`는 1~10이라 k=9까지 가능(1.5·9²=121.5). 237 로스터(등급 1~9)에서 k=8 → 96 > 60이 실현 가능 = **재결성이 밴드 확장보다 싸다.** → W_GROUP4 **125** 필요.
3. `commitTeammates`에 팀당 ghost≤1 캡이 없다(`maxPlaying`은 `autoFillTarget`에만 전달). 경기41 종료 2초 뒤 경기42에 2명 승계 실측.
4. 완료 undo·확인 다이얼로그 부재 → 4분 미만 완료 5건(0.1/2.9/3.0/3.4/3.5분). 허수 gc + 허수 groupHistory + reunion4 2건의 원인.
5. `lastGameType`이 `resyncFromServer` patch에 없다 — 복구 경로가 리로드뿐. rotate 항 실측 영향폭 중앙값 20.0 > group 16.0.
6. `pairPlayers.bestMixedPairing`이 혼복 여성 2명을 **반드시 다른 팀**에 배치(2F vs 2M 조합이 후보에 없음) → 여성끼리는 늘 맞대결. 송수민 9판 중 5판(56%)이 안정은과 맞대결.
7. `rankCandidates` `confirmed.length === 0` 조기반환이 skill·group을 통째로 건너뛴다 → 새 팀 첫 픽에 재결성 회피 미적용.
8. `matches.assign_source` 부재 — `autoFillTarget`/`commitTeammates`/`handleDrop`이 DB에서 원리적으로 구별 불가. **이게 없으면 다음 감사도 같은 벽에 막힌다.**

### 겹침의 충분통계는 μ이지 코트 수가 아니다

μ = 6M / C(N,2) (M=경기수, N=인원). corr(log μ, overlap2) = **+0.973**(n=35). 세션 73이 좋아 보였던 건 알고리즘이 아니라 μ가 0.562로 237(1.544)의 1/2.7이었기 때문. **§4/§4b의 절대 수치를 인원·코트가 다른 세션과 직접 비교하지 말 것.**
부수: 코트를 늘리면 악화(19명·4코트는 overlap3 +1.0pp, ghost 15→29팀). 혼복 비율은 2F/N = 42.1%가 성별 균등 참여의 유일해라 건드리면 여성 출전이 같은 비율로 준다.

## 4d. 세션 간(cross-session) 반복 — 단일 세션 감사가 놓치는 축

**§4·§4b·§4c는 전부 한 세션 안만 봤다. "매번 같은 사람과 친다"는 민원의 상당 부분은 세션을 가로질러 쌓인다.**

`fetchSessionSnapshot`(`src/lib/supabase/session.ts:30`)이 completed matches를 `.eq("session_id", sessionId)`로만 조회한다 → **groupHistory는 세션 스코프이고 재결성 회피 기억은 매주 리셋된다.** 같은 로직이 매주 같은 사람을 다시 붙일 수 있다.

### 방법

7/1~8/17 closed 세션 35개·완료 1,069경기를 `session_players.member_id`로 통합. 귀무는 **세션별로** 코트 점유·경기별 실제 성별 구성·선수별 활동구간(첫 경기~마지막 경기)을 보존한 채 사람만 재배치(200회).

### 결과 (자유도가 충분한 22명+ 세션 12개·560경기만, 단골 39명·741쌍)

| 지표 | 실측 | 귀무 | z |
|---|---|---|---|
| 등급거리 ↔ 동반횟수 상관 | −0.259 | −0.115 ± 0.023 | **−6.32** |
| 상위 10쌍 동반 합 | 152 | 124.8 ± 6.5 | **+4.19** |
| 최다 동반 쌍 | 25회 | 15.5 ± 1.7 | **+5.59** |

전체 35세션(단골 54명)에서도 z −8.31 / +4.77 / +4.62. **소규모 세션 탓이 아니다.**
개별 사례: 이수민(F) 77판 중 41판(53%)을 표슬아(F)와 — 같은 귀무 기대 23%(z=+5.9). 세션 131은 7판 전부, 세션 76·159는 9판 중 8판. 세션 76은 여성이 11명 있던 세션이다.

### 해석 — 단기 반복과 장기 경향은 방향이 반대다

세션 237 한 판만 보면 실측(쌍 등급거리 2.42)은 무작위(2.62)와 알고리즘 설계치(2.29) 사이에서 **무작위 쪽**이다. 그런데 7주를 누적하면 실측(r=−0.259)이 **알고리즘 설계치 쪽**(full 시뮬 r=−0.311)에 붙는다.
즉 **매 세션의 약한 등급 매칭 편향이 세션 간 기억 없이 35번 반복되며 누적된다.** 자동편성을 더 충실히 쓰면 세션 내 반복(overlap3·개인 최다동반)은 좋아지지만 **이 축은 오히려 강해진다.** 두 목표를 같은 다이얼로 못 잡는다.

### 함정 추가 (§3에 준함)

8. **단일 세션 z로 계통 편향을 판정하지 말 것.** 세션당 z는 −1.5~−1.9로 전부 tie 판정이 나오지만 Stouffer 결합은 −3.74다. 약한 편향 × 반복이 체감을 만든다.
9. **member 키 분열 확인.** 108명 중 11명이 이름 하나에 키 2~3개(게스트 재등록 등) → 그 인원의 교차세션 이력이 쪼개져 **과소집계**된다. 위 수치는 그만큼 보수적이다.
10. 최다 쌍 지목은 다중비교다. 171~1431쌍 중 사후 최댓값을 인용하려면 귀무도 **최댓값 분포**로 비교할 것(위 표의 "최다 동반 쌍"이 그 방식).

### 처방 후보 (미측정 — 적용 전 시뮬 필요)

- `groupHistory`에 **최근 N세션의 4인 그룹을 감쇠 가중**으로 싣는다. 세션 스코프 리셋이 근본 원인이므로 여기가 정면이다. 다만 판수 형평(W_GAME)과 충돌하지 않는 세기를 스윕으로 정해야 한다.
- 위가 무거우면 **회원별 "최근 4주 최다 동반 상대" 배지**를 보드 자석에 노출해 운영자 판단에 맡기는 저비용 대안.

## 5. 빠른 시작
