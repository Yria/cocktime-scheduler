# 콕타임 (CockTime) 서비스 기획서

> **팀매칭은 [팀매칭 기획](TEAM_MATCHING_SPEC.md)을 기준으로 읽는다.** 사용자 흐름·참여 조건·자동편성·회원 파티를 통합했고, [정합성 검토](TEAM_MATCHING_REVIEW.md)에 기획·구현 차이를 기록했다(2026-09-07). 이 문서의 팀매칭 요약도 함께 정정했다. 다른 화면의 역사적 설명은 이번 검토 범위가 아니다.

## 1. 서비스 개요

배드민턴 클럽의 정기 모임(세션)을 운영하는 도구.
선수 명단을 관리하고, **자석 칠판(보드)** 위에서 코트별 팀을 직접 편성하며, 대기/경기/휴식 상태를 실시간으로 공유한다.

- 타깃: 배드민턴 클럽 관리자 + 참석 선수 전원
- 환경: 모바일 전용 (PC는 모바일 레이아웃 그대로)
- 실시간 동기화: 관리자 태블릿 + 참석자 개인 스마트폰이 같은 세션 화면을 공유

> **2026-06 리팩토링 반영**
> 기존의 다전략 팀 후보 일괄 생성 + 별도 DB 매치 대기열(match queue) + pending(미도착) 상태 +
> 수동매칭 로그(manual match logs) + 팀 후보(team candidates) 슬라이스를 **전부 제거**했다.
> 현재는 **보드 수동 드래그·추천·자동 채움**과 **회원 파티**를 사용한다. 보드의 ghost 예약과 매칭확정 순번도 유지된다.
> - 라우팅: `/session` = 보드(SessionBoard, PixiJS WebGL 자석 칠판). 구 `/session/board` 는 `/session` 으로 리다이렉트. 구 `/session`(SessionMain)은 삭제됨.
> - 추천 로직(`recommendTeammates` / `rankCandidates` / `pairPlayers` / `skillScore`)은 **유지**된다.

## 2. 화면 구성

### 2-1. 홈
- 구글 스프레드시트 URL 입력 → 선수 데이터 로드
- 로드된 선수 목록 확인 후 세션 설정 페이지로 이동

### 2-2. 세션 설정
- **코트 수 선택** (1~6개)
- **남복 편성 허용 여성 지정**: 남3여1에서 성별 추천 비용을 면제하고 유형을 `혼합`으로 분류할 여성 선택. 현재 미허용 구성을 금지하는 검증은 아님([팀매칭 기획 §7](TEAM_MATCHING_SPEC.md#7-게임-유형과-2v2-편성))
- **참석자 선택**: 전체 선수 목록에서 오늘 참석한 선수를 체크. 이름 검색, 성별 필터 지원
- **게스트 추가**: 명단에 없는 임시 참가자 추가 (이름·성별·스킬 입력)
- 세션 시작 버튼 → 세션 생성 후 보드 페이지(`/session`)로 이동

### 2-3. 세션 보드 (세션 메인)
세션 진행 중 메인 화면. **PixiJS WebGL 기반 자석 칠판.**

#### 표시 영역
| 영역 | 내용 |
|------|------|
| 코트 | 코트별 현재 경기 중인 팀 A / 팀 B (자석) |
| 대기 영역 | 경기 대기 중인 선수 자석 |
| 휴식 영역 | 일시 휴식 중인 선수 자석 |
| 팀 구성 영역 | 코트 배정 전 4명을 모아두는 임시 그룹(보드 드래프트) |

#### 헤더 / 푸터 (UI chrome)
- **헤더**: 앱 글래스 톤앤매너(`var(--mat-thick)`/`lq-header`/`lq-bar`) 적용. 우측에 [설정](→`/setup`), [로그](→`/logs`), [세션 종료] 버튼. "뒤로" 버튼은 제거됨.
- **[세션 종료]**: 확인 모달 → `handleEndSession` → `sessions.is_active=false` + 본인 `navigate("/")`. 다른 클라이언트는 `is_active` postgres watch 로 종료 감지.
- **정렬**: 우하단 **플로팅 버튼**으로 이동(헤더에서 분리).
- **세션 설정 화면(SessionSetup) 헤더**: 뒤로 버튼 추가 — 활성 세션이면 `/session`(보드)로, 없으면 `/`(홈)로.

#### 액션
- **자석 드래그**: 선수 자석을 대기/팀 구성/코트/휴식 영역으로 직접 끌어 배치
- **추천 팀원**: 팀 구성 영역의 빈 슬롯(+)을 누르면 현재 멤버에 가장 어울리는 후보 순위를 추천 (`recommendTeammates`)
- **자동편성**: 추천 모달에서 직접 고른 사람을 유지하고 남은 자리를 한 명씩 재평가하며 채움
- **매칭확정·코트 배정**: 출전 가능한 4명을 확정해 순번 표시 → 운영진이 빈 코트에 경기 시작(`assign_match` RPC). 순번은 안내이며 강제 출전 순서는 아님
- **회원 파티**: 참가 운영진 전원이 경기 중이면 읽기 모드 회원이 5초간 버튼을 누르는 모집에 참여. 유효 참가자 중 4명을 선발해 확정 팀 생성
- **경기 완료**: 최종 참가자 대기 복귀, `game_count` 증가·대기시간 리셋·혼복 남성의 `mixed_count` 증가. 재결성 이력은 완료 `matches`에서 파생하며 `pair_history`는 삭제됨
- **휴식 전환**: 대기 ↔ 휴식 토글
- **세션 종료**: 헤더 [세션 종료] 버튼(위 헤더 항목 참조)

> **세션 종료(유지)**: 보드 헤더 [세션 종료] 버튼 → 확인 모달 → `handleEndSession` → `sessions.is_active=false` + 본인 `navigate("/")`.
> 다른 클라이언트는 `is_active` postgres watch 로 종료를 감지한다(`session_ended` 브로드캐스트는 미사용).
>
> **제거됨(deprecated)**: 과거 다전략 후보 일괄 생성·별도 DB 매치 대기열,
> 혼복 우선배치(`force_mixed`)·빡겜 우선배치(`force_hard_game`).
> 현재 보드의 자동 채움·ghost 예약·매칭확정 순번·회원 파티와 구분한다.
> (`force_mixed`/`force_hard_game` 은 기능·DB 컬럼 모두 제거됨 — 상세는 5절 상태 머신 참고.)

## 3. 핵심 기능 상세

### 3-1. 보드 추천 로직 (recommendTeammates)

선택된 멤버에 맞춰 후보를 비용 오름차순으로 추천한다. 판수·실력·그룹 이력·대기 비용 위에 유형 로테이션·성별 구성·경기 중 비용을 더한다. 직접 선택용 추천 모달에는 경기 중 비용을 해제하는 별도 예외가 있으며, 자동편성과 후보 범위·상한도 다르다. [팀매칭 기획 §4·§5](TEAM_MATCHING_SPEC.md#4-전체-흐름) 참조.

가중치·정확한 공식의 상세 기준은 [TEAM_GENERATION_RULES](TEAM_GENERATION_RULES.md)다. 상위 기획에서는 수치를 중복 관리하지 않는다.

### 3-2. 후보 점수 (rankCandidates)

선택된 멤버를 기준으로 실력 범위 확장·과거 완료 경기와의 그룹 겹침·새 만남·보정 판수·대기시간을 합산한다. 아직 함께 경기하지 않은 사람을 만나는 구성을 우대하며, 첫 선발은 현재 후보들 중 만남 폭이 좁은 사람도 우대한다. 당일 세션 기준으로 상대편도 만남에 포함한다. 판수 형평을 중시하지만 절대 우선순위는 아니다. 동점은 입력 순서를 유지하고, 대기 비용은 계산 시각에 의존한다. [새 만남 보정과 검증](TEAM_MIXING_VALIDATION.md) 참조.

> **제거됨(deprecated)**: deficit(기대 경기수 적자) 모델, 쌍 단위 동반 회피(`pairOverlap`·`W_PAIR`·`pair_history` 조회), 혼복 "여자만" 실력 균형, 가중치 프로필 `WEIGHT_PROFILES`. 상세 이력은 TEAM_GENERATION_RULES 부록.

### 3-3. 페어 편성 (pairPlayers)

선발한 4명을 유지한 채 두 편의 실력 합 차이와 편 내부 실력 차이를 평가한다. 혼복은 남녀 한 명씩인 두 가지 조합, 그 외는 세 가지 조합을 비교하며 최저 비용 동점일 때만 랜덤이다. 경기 유형 표와 분류상 한계는 [팀매칭 기획 §7](TEAM_MATCHING_SPEC.md#7-게임-유형과-2v2-편성), 공식은 [알고리즘 규칙 §6](TEAM_GENERATION_RULES.md#6-페어-편성--pairingscore--pairplayers) 참조.

### 3-4. 실시간 동기화

- Supabase Realtime 이벤트와 DB 상태 조회를 함께 사용한다.
- 시작·완료·로스터 이벤트로 즉시 반영하고, 보드·선수 상태는 해당 동기화 경로로 공유한다.
- 재연결 시 서버 상태를 조회한다. 직전 경기 유형의 복구 누락은 [정합성 검토 R3](TEAM_MATCHING_REVIEW.md#r3-재연결-복구에서-직전-경기-유형이-누락)에 기록했다.

## 4. 선수 데이터 구조

| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | `Player.id`: 회원은 `members.id`, 세션 설정 게스트는 `guest-*` 원본 ID |
| name | string | 이름 |
| gender | 'M' \| 'F' | 성별 |
| skills | object | `{ grade: 1~10 }`, 10이 가장 높음 |

경기·추천·예약에서는 위 원본 ID와 별개인 `SessionPlayer.id`(`session_players.id`)를 사용한다. 과거 O/V/X·상/중/하 스킬은 읽을 때 등급으로 환산하는 하위호환만 유지한다. 자세한 의미는 [팀매칭 기획 §2](TEAM_MATCHING_SPEC.md#2-용어와-데이터) 참조.

## 5. 선수 상태 전이

```
[waiting] ──배정──▶ [playing] ──완료──▶ [waiting]
    │
    ├──휴식──▶ [resting] ──복귀──▶ [waiting]
```

- **waiting**: 대기 상태. 콕 체크가 켜져 있으면 콕 확인도 완료해야 일반 편성 대상
- **playing**: 코트에서 경기 중
- **resting**: 일시 휴식, 추천 대상에서 제외

> **제거됨(deprecated)**: `pending`(미도착) 상태와 활성화 전이. 세션 시작 시 전원 `waiting`으로 등록된다.
> `force_mixed`(혼복 우선배치)·`force_hard_game`(빡겜 우선배치)는 **기능·DB 컬럼 모두 제거**됐다.
> 토글/쓰기 경로뿐 아니라 DB 컬럼까지 마이그레이션 `20260612120000` 에서 DROP 됐고,
> 코드 필드·transformer·타입·`DebugMatchModal` 표시도 전부 삭제되어 더 이상 어디서도 참조하지 않는다.

## 6. 세션 라이프사이클

```
세션 생성 → 참여자 전원 waiting 등록
    ↓
[반복] 보드에서 4명 구성 → 매칭확정 → 코트 배정 → 경기 완료 → 대기 복귀
```

> **세션 종료**: 보드 헤더 [세션 종료] 버튼으로 가능하며, 세션 활성/비활성은 `sessions.is_active` 로 관리한다(`dbEndSession` → `is_active=false`).
> 종료 전파는 `is_active` postgres watch 로만 이뤄진다(`session_ended` **브로드캐스트 이벤트는 미사용**).

## 7. 비고

- 경기 득점·승패 계산 없음. 추천·페어 편성의 내부 비용 계산은 사용
- 세션 간 통계/히스토리는 현재 범위 외 (추후 확장)
- 게스트 선수는 구글 시트에 없는 임시 참가자 (`guest-` prefix ID)
