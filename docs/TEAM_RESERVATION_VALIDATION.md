# 자동편성의 경기 중 예약 1명 제한 해제

> 2026-09-07 · 로컬 코드 반영. 앱 배포 전.

운영진 자동편성에서 경기 중인 사람을 팀당 1명만 예약하던 제한을 제거했다. `대기 2명 + 예약 2명`, `대기 1명 + 예약 3명`을 허용하며 기존 예약이나 수동 선택 때문에 추가 예약이 막히지 않는다. 현재 보드는 대기 정식 멤버(anchor)가 최소 1명 있어야 팀을 생성·유지하므로 경기 중인 4명만의 예약 전용 팀은 지원하지 않는다.

선발은 기존 합산 점수를 사용한다. 새 만남 보너스는 12, 경기 중 후보 비용은 30이다. 다른 팀에 이미 예약된 선수는 자동 후보에서 제외한다. 회원 파티는 대기 선수만 선발한다. 구체적인 조건은 [알고리즘 규칙 §8](TEAM_GENERATION_RULES.md#8-자동편성--autofillteammates)을 따른다.

예약자는 자기 경기가 끝나는 순서대로 합류하며 마지막 예약자까지 돌아와야 매칭확정할 수 있다. 선택 시점에 각 경기의 남은 시간이 `r₁, …, rₖ`라면, 경기 종료를 기다리는 시간은 그 합이 아니라 `max(r₁, …, rₖ)`이다. 실제 시작은 빈 코트·운영진 조작에도 의존한다. 현재 추천 점수는 남은 경기 시간을 예측하지 않는다.

## 비교 방법

실제 추천·자동편성·페어 함수를 호출하는 [합성 시뮬레이션](../scripts/team-mixing-simulation.test.ts)에서 새 만남 가중치 12를 고정하고 예약 1명 제한과 새 정책을 비교했다. 빈 새 팀을 자동편성하므로 새 정책은 `maxPlaying=3`으로 대기 한 자리를 확보한다.

- 합성 로스터 6종 × 시드 10001~10200 × 두 정책 = **2,400세션, 115,200완료 경기**.
- 한 세션 48경기, 경기 시간 10~15분. 같은 시드끼리 선수 입력 순서와 경기 시간 난수열을 맞춘다.
- 예약한 사람이 모두 돌아오면 시작한다. 중복 예약·한 경기 중복 선수·두 코트 동시 점유·완료 판수 보존·대기 anchor 조건을 검사한다.
- 빈 코트마다 팀을 만드는 모형이다. 운영진의 수동 개입·휴식·중도 퇴장·예비팀 사전 대량 구성은 포함하지 않는다.
- 이 시드는 [이전 새 만남 보너스 실험](TEAM_MIXING_VALIDATION.md)에서도 사용했다. 이번 정책을 새로 조정한 뒤의 독립 검증이라고 해석하지 않는다.

## 결과

각 값은 200세션 평균, `1명 제한 → 여러 명 허용` 순서다. 만남은 같은 경기의 4명 안에서 파트너·상대를 모두 포함한다. 대기 p95는 합류 또는 직전 종료부터 다음 경기 시작까지의 대기시간 95백분위 평균이며 마지막 경기 이후의 대기는 제외한다. 여러 명 예약 비율은 새 정책에서 경기 중 선수 2명 이상을 함께 선택한 팀의 비율이다.

| 조건 | 못 만난 쌍 | 대기 p95(분) | 코트 가동률 | 여러 명 예약 비율 |
| --- | --- | --- | --- | --- |
| 24명 · 남12/여12 | 47.055 → 47.055 | 23.60 → 23.60 | 97.29% → 97.29% | 0.01% |
| 24명 · 남18/여6 | 41.430 → 41.505 | 24.44 → 24.44 | 96.70% → 96.70% | 0.03% |
| 24명 · 2/8등급 양분 | 83.760 → 84.160 | 24.19 → 24.20 | 96.07% → 96.12% | 0.54% |
| 16명 · 남12/여4 | 0.205 → 0.225 | 14.92 → 14.99 | 88.31% → 88.17% | 2.32% |
| 28명 · 45분에 4명 늦참 | 119.970 → 120.020 | 27.08 → 27.10 | 97.44% → 97.43% | 0.04% |
| 8명 · 동일 등급 · 2코트 | 0 → 0 | 15.16 → 3.73 | 76.12% → 93.20% | 37.29% |

24~28명에서는 여러 명을 예약하는 비율 자체가 낮고 만남 범위 변화도 작았다. 경기 중 비용 30과 다른 선발 비용이 계속 작동하기 때문이다. 16명에서는 대기 p95가 약 0.07분 늘고 가동률이 약 0.14%p 낮아졌다. 8명 조건에서는 이미 양쪽 모두 전원이 서로 만났으며, 여러 명 예약 허용 후 대기시간과 가동률이 개선됐다.

이번 비교에서 보정 판수 표준편차 증가의 최댓값은 약 0.008판(16명)이었다. 8명은 0.280 → 0.005판이었다. 편 간 등급 합 차이 평균의 증가 최댓값은 약 0.0003이었다. 전체 지표와 같은 시드 차이의 표준오차(SE)는 [집계 JSON](TEAM_RESERVATION_VALIDATION.json)에 보관한다.

**1명 제한 해제만으로 만남 범위가 더 넓어진다는 결론은 나오지 않았다.** 일부 조건에서는 못 만난 쌍 평균이 소폭 증가했다. 따라서 이전 보너스 실험의 ‘미만남 쌍 증가 없음’ 기준을 이번 변경도 모두 통과했다고 표현하지 않는다. 이번 변경은 예약 가능한 조합을 넓히며, 실제 운영의 개선 비율이나 모든 참가자 간 만남을 보장하지 않는다.

## 재현과 회귀 검사

```sh
MIXING_SEEDS=200 MIXING_SEED_START=10001 MIXING_WEIGHTS=12 MIXING_PLAYING_LIMITS=1,3 MIXING_OUTPUT=/tmp/cocktime-multiple-reservations.json pnpm exec vitest run --config scripts/team-mixing-simulation.config.ts --reporter=dot
pnpm exec vitest run src/lib/teamSelection src/lib/board src/store/boardStore.test.ts src/lib/supabase/transformers.test.ts src/lib/supabase/transformers.groupHistory.test.ts --reporter=dot
```

[보드 회귀 검사](../src/store/boardStore.test.ts)는 한 번에 2명 예약, 기존 예약 이후 추가 예약, 수동 선택 이후 자동 채움, 대기 anchor 확보, 타 팀 예약자 제외, 3개 경기의 순차 종료 후 합류·확정, 예약 3명 팀의 원격 동기화를 확인한다. 관련 회귀 검사는 21개 파일·325개 테스트를 통과했다.

변경한 TypeScript 파일의 ESLint와 `pnpm run build`도 통과했다. 빌드는 기존 청크 크기·정적/동적 import 중복 경고를 남겼다.
