# 팀 편성 시뮬레이터

2026-09-16 조회 당시 실제 출전자 30명인 최신 모임(2026-09-08, 세션 183)의 명단과 첫 완료 경기 당시 실력으로 세 알고리즘을 비교한다. 2026-09-18 중복+실력 정책을 운영 소스에 이식했다. 비교군 ①은 이식 전 함수를 `baseline/`에 보존해 과거 결과가 바뀌지 않게 한다. DB 배포는 수행하지 않는다.

## 사용

실제 회원이 포함된 `input.json`과 분석 결과는 공개 저장소에 포함하지 않는다.
로컬 분석 입력은 필요한 권한을 갖춘 환경에서 `python3 tools/team-simulator/fetch-input.py`로 생성한다.
자동 테스트는 `test-roster.ts`의 합성 명단으로 실행되므로 운영 데이터가 필요 없다.

`reports/team-simulator-20260916/index.html`을 브라우저에서 연다. 외부 요청이나 계정 없이 동작하며 경기 수, 코트 수, 시드, 반복 횟수, 실력 가중치·반영 방식·교류 간격 기준·참가 인원·출전 정책·이전 정책의 코트 대기 상한·늦참 인원·합류 시각·판수 보정을 변경해 다시 계산할 수 있다. 평균 차트와 선택 시드의 개인별 동반 막대그래프를 제공한다. 차트별 SVG 저장을 지원한다.

## 알고리즘

- 현재: 이식 전 운영 코드 `baseline/recommendTeammates.ts`의 `autoFillTeammates`를 import한다. 새 기본 모드에서는 대기/경기 중 후보를 모두 넘기고 `maxPlaying=3`으로 호출한다. 함수 자체는 수정하지 않는다. 아래 공통 실험 조건의 재계산 모형을 적용하므로 운영 앱의 실제 예약 대기열 전체를 재현한 것은 아니다.
- 개선: 먼저 남4, 여4, 남2여2, 여성 등급이 **4 이상**인 여1남3만 허용한다. 3점 이하는 제외하고 4점부터 허용하며 이전 `allowMixedSingle` 플래그로 이 조건을 우회하지 않는다. 남1여3은 제외한다. 현재 비교군은 기존 코드를 그대로 쓰므로 이 조건 밖의 구성이 나올 수 있다.
- **출전 가능 여부가 첫 우선순위다.** 대기자로 허용된 팀을 만들 수 있으면 경기 중인 후보를 제외한다. 반복·실력·판수 점수로 이 조건을 뒤집을 수 없다. 불가능할 때만 경기 중인 인원 수를 먼저 최소화해 잠정 후보를 만든다. 대기자 한 명 이상이 필요하며 경기 중인 인원은 최대 3명이다. 휴식·미확인 후보는 제외한다.
- 남은 대기 인원으로 동시에 만들 수 있는 허용 경기 수가 줄어드는 선택도 제외한다. 예를 들어 남6·여2(4점 이상 1명, 3점 이하 1명)에서 여1남3을 먼저 만들면 남은 네 명이 경기할 수 없으므로 남4/남2여2를 선택한다. 성별 인원별 동적 계획으로 가능한 경기 수를 계산한다. 2대2 파트너 편성은 하지 않는다.
- 이후 `(출전 초과분, max(0, 과거 경기와 최대 공통 인원 - 1), 누적 동반 쌍 횟수, 보조 점수)`를 사전식으로 최소화한다. 출전 초과분은 `Σ max(0, 개인 추천용 판수 - 대기자 최저 판수 - 1)`이다. 새 만남이 많다는 이유만으로 이미 2판 이상 앞선 사람을 반복 우대하지 않는다. 모든 허용 조합에 초과자가 필요하다면 초과분이 가장 작은 조합을 사용한다. 0명과 1명 공통은 동일하게 취급한다.
- 개선 + 실력의 이전 방식(`nearby`): 위 보조 점수에 `skillWeight × (최고 등급 - 최저 등급)²`를 더한다.
- 개선 + 실력의 새 기본 방식(`exchange`): `skillWeight × [실력 범위² + 81 × ΔΣᵢ(rᵢ/K)²]`를 더한다. `rᵢ`는 개인별로 목표 실력대와 만나지 못한 연속 출전 횟수, `K`는 조절 가능한 간격 기준(기본 3경기), Δ는 후보 경기 완료 전후의 변화다. 81은 등급 1~10의 최대 범위²다. 교류하면 해당 개인의 r을 0으로, 아니면 1 증가시킨다. 쉬거나 다른 사람이 경기하는 동안에는 늘지 않고, 여러 번 교류해도 미래 교류를 면제하는 잔고가 생기지 않는다.
- 분석용 구간: 하위 1~3, 중위 4~6, 상위 7~10. 하위는 상위, 상위는 하위를 만나야 교류로 인정한다(중위를 만나는 것만으로 상·하위 공백을 해소하지 않음). 중위는 다른 구간을 만나면 인정한다. 반대 구간 자체가 없는 명단은 존재하는 다른 구간으로 대체하고, 단일 구간이면 교류 항이 0이다. 회원에게 등급을 노출하는 기능은 추가하지 않는다.
- 교류 공백이 길수록 같은 실력 범위 벌점을 더 강하게 상쇄한다. 그래도 중복 최소화의 두 우선순위는 앞에 있으므로 정해진 경기 안의 교류나 모든 상·하위 개인 쌍의 만남을 보장하지 않는다. K는 우선순위 강도를 정하는 실험값이며 강제 주기가 아니다. 휴식·귀가가 있는 운영 적용 시에는 당시 참여 가능한 목표 구간을 갱신해야 한다.
- 어느 실력 방식이든 가중치 0이면 개선안과 정확히 동일하다. UI에서 이전 방식으로 전환해 같은 세 비교군으로 재실험할 수 있다.
- 보조 점수: 개인별 `10×추천용 판수 - 대기 분`, 직전 경기 유형 반복 +6 / 전환 -6. 판수·대기·전환 가중치는 현재 상수를 import한다. 성별은 이제 점수 벌점이 아닌 허용 조건이다.
- 파트너·상대 배치는 평가하지 않는다. 개선안에서는 남4=남복, 여4=여복, 남2여2=혼복, 허용된 여1남3=혼합으로 전환 선호를 계산한다. 정해진 경기 유형 비율을 강제하지는 않는다.

## 공통 실험 조건

기본은 전원 동시 참가이며, 선택적으로 고정 시드로 고른 일부 참가자의 합류 시각을 늦추는 가정 실험을 한다. 휴식·조기 귀가는 없다. 새 기본 `selectionPolicy=ready-first`에서는 현재 함수도 경기 중 후보를 받을 수 있고, 개선안 두 가지는 대기자 우선을 강제한다. 준비된 허용 팀은 즉시 시작하며 중복 때문에 1분을 기다리지 않는다.

빈 코트가 있으면 후보를 계산한다. 후보에 경기 중인 사람이 있으면 다음 경기 종료 또는 합류 시점까지 실제 출전을 보류하고, 그때 후보를 새로 계산한다. 잠정 후보는 대기자나 코트를 독점하지 않는다. 모든 코트에 같은 후보 풀이 들어가므로 상태 변화 없이 동일 후보를 다시 세지는 않는다. 수동 고정 멤버·확정 예약 대기열·이동·호출·물 마시기 시간은 모형에 포함하지 않는다. 따라서 실제 앱 예약의 지연 시간을 그대로 측정한 결과가 아니다.

`score-first`는 같은 풀·경기 길이·이벤트 모형에서 **②·③의 대기자 우선 조건만 해제한 가정 대조군**이다. 경기 중 벌점 30점과 나머지 점수·허용 구성은 유지하지만, 경기 중 인원 수를 첫 우선순위로 최소화하지 않는다. ①의 결과는 새 기본 모드와 같다. 이전 개선 알고리즘을 의미하지 않는다.

`legacy-wait`는 이전 시뮬레이터 조건을 재현한다. 세 방식 모두 대기자만 후보에 넣고(`maxPlaying=0`), 준비된 네 명이 각자의 직전 경기 중 하나와 3명 이상 겹치고 다른 코트가 경기 중일 때만 코트가 빈 시점부터 설정한 상한까지 기다린다. 상한 0이면 바로 시작한다. `courtWaitSeconds`는 이 모드에서만 사용한다. 이전 실험에서는 경기 중인 사람을 고르는 문제를 처음부터 관찰할 수 없었다.

각 시드의 입력 순서와 경기 시작 순번별 10~15분 균등분포 경기 길이는 세 알고리즘에서 동일하다. 정책에 따라 실제 시작·종료 시각은 달라진다. 선정은 미래 종료 시각을 읽지 않는다(이벤트 시계만 종료 시각을 이용한다). 상태·경기 이력은 각 방식에서 독립적이며, 날짜 함수는 현재 알고리즘 호출 동안 가상 시각으로 바꾸고 즉시 복원한다. 마지막 경기까지 전부 완료한다.

기본 경기 수 55는 실제 완료 경기 수를 맞춘 값이다. 실제 스케줄이나 도착·휴식 상태를 복원한 것이 아니므로 실제 운영 결과와 동일하다고 해석하지 않는다. 공통 이벤트 모형에서의 네 명 선정 정책 비교이며 운영 앱 전체를 복원한 실험은 아니다.

## 지표

- 경기 중 포함 후보: 빈 코트에서 재계산한 후보 중 경기 중 인원이 포함된 횟수. 실제 경기 수·서로 다른 예약 팀 수가 아니며 같은 후보가 반복될 수 있다.
- 불필요한 경기 중 포함 후보: 위 횟수 중, 당시 대기자만으로 허용 팀을 만들 수 있었던 경우. 인원 수뿐 아니라 성별·여성 4점 조건까지 판단한다.
- 시작 가능했던 코트 공백: `min(빈 코트 수, 대기자로 만들 수 있는 서로 겹치지 않는 허용 팀 수, 남은 경기 수) × 다음 이벤트까지 시간`의 누적. 단위는 코트·분이며 두 코트가 1분씩 비면 2분이다. 마지막 경기 시작 후 정리 구간은 제외한다. 인원·성별 조건 때문에 불가능했던 시간은 이 지표에 포함하지 않는다.

- 공통 인원 분포: 세션 내 서로 다른 모든 경기 쌍 `M(M-1)/2`을 비교. 2명 이상부터 중복. 1명 겹침은 중복에 포함하지 않는다.
- 고유 동반: 같은 경기에 들어간 모든 쌍을 계산. 파트너/상대 구분 없음. 30명이면 한 사람당 최대 29명, 전체 최대 435쌍.
- 실력 범위: 경기별 최고 등급−최저 등급의 평균. 랠리의 직접 측정값이 아니다.
- 출전 편차: 30명의 실제 가상 출전 횟수 표준편차. 늦참 보정값을 포함하지 않는다. 참가 시간이 다른 경우 이 수치만으로 공평함을 판단하지 않는다.
- 최대 대기: 각 출전 전 대기와 마지막 시점의 미출전 대기를 포함한다.
- 실력대 교류: 각 구간 사이 가능한 고유 쌍 중 만난 비율. 이번 명단은 하위 11명, 중위 9명, 상위 10명이므로 하위·상위 분모는 110쌍이다. 횟수가 많은 특정 쌍으로 부풀리지 않는다.
- 교류 공백: 각 실행에서 상·하위 개인별 최장 미교류 연속 출전을 계산하고 그중 최댓값을 집계한다. 첫 교류 전과 마지막 교류 후도 포함한다. 함께 표시하는 미동반 인원은 반대 구간을 한 번도 못 만난 상·하위 참가자 수이며 미출전자도 포함한다. 구간이 없으면 가능한 쌍과 해당 대상자가 없으므로 두 지표는 0이다.
- 코트 가동률: 첫 시작~마지막 시작까지 전체 코트 시간 대비 실제 경기 시간. 마지막 경기 이후 정리 구간은 제외한다. 시작이 모두 동시인 한 차례 실험은 마지막 종료를 분모로 쓴다.
- 코트 공백: 같은 코트의 연속한 두 경기 사이 초 단위 간격(0초 포함)의 평균과 최댓값. 총 공백 분은 가동률과 같은 구간의 모든 코트별 빈 시간 합계이며 실제 경과 시간과 다르다.
- 동일 네 명 연속 재경기: 네 사람 모두 각자의 직전 경기와 동일한 네 명인 경기 수 / 전체 경기 수. 파트너 배치는 무관하다.
- 경기 구성: 실제 네 명의 성별·여성 등급으로 남복/여복/혼복/허용 여1남3/조건 밖 구성을 분류한다. 기존 함수의 게임 유형 라벨과 다를 수 있다.
- 늦참 후 출전 빈도: 마지막 합류 시점부터 최대 30분(모임이 먼저 끝나면 그때까지)의 동일 구간에서 집단별 1인당 경기 시작 수를 시간당으로 환산한다. 도착 전에 시작한 경기는 제외한다. 관찰 시간이 없으면 0이고 관찰 시간도 표시한다.
- 5~95백분위: 반복 시뮬레이션 결과의 변동 범위. 실제 효과의 신뢰구간이 아니다.

프로젝트 의존성을 설치한 후 루트에서 실행한다. 별도 패키지를 추가하지 않는다.

```sh
# 자격증명을 출력하지 않는 읽기 전용 조회. 저장된 입력 재사용 시 생략.

node node_modules/vitest/vitest.mjs run --config tools/team-simulator/vitest.config.ts
node node_modules/typescript/bin/tsc -p tools/team-simulator/tsconfig.json
node tools/team-simulator/build.mjs
node tools/team-simulator/qa.mjs
```

HTML UI의 기본 컨트롤은 빌드된 결과 설정에 맞춰 초기화된다. `results.json`(새 실력 방식), `nearby-results.json`(동일 조건의 이전 실력 방식), `capacity-results.json`, `late-results.json`, `availability-results.json`(새 정책/우선순위 해제/이전 시뮬), `availability-scenarios.json`(16/20/24/30명), `input.json`, `provenance.json`과 현재 알고리즘 소스 사본을 함께 보존한다. ## 늦참 보정

- 도착 전에는 선정 풀과 평균에서 제외하고, 도착 시 대기를 시작한다. 중복 회피 이력을 만들어 넣지 않는다.
- 추천용 시작 판수는 기존 활성 참가자(waiting/playing, 확인 완료)의 추천용 판수 평균을 반올림한다. 진행 중인 1판은 추가하지 않는다. 같은 시각의 여러 늦참자는 합류 전 집단의 같은 기준을 받는다.
- 저장소의 `20260907040000_late_join_game_count.sql`과 같은 평균 기준을 모사한다. 운영 DB 적용 여부를 이 시뮬레이터에서 확인하거나 변경하지 않는다.
- 실제 출전 수는 경기 기록에서 별도로 계산한다. 예를 들어 기존 평균이 4판이면 새 참가자의 추천용 시작값은 4, 실제 기록은 0이다. 이름별 상세에서 보정값을 확인할 수 있다.
- ②·③은 위 출전 초과분 보호도 함께 사용한다. 보정이 있다고 모든 사람의 단기 출전 빈도가 완전히 같아지는 것은 아니다. 직전 경기 종료 시각, 성별 구성과 가능한 후보의 영향은 남는다.
- UI의 ‘보정 없음’은 실험용 대조 조건이며 세 비교군 모두에 적용된다. 기본은 평균 보정이다. `late-results.json`에 30명 중 4명이 30분 후 합류한 20회 실험의 보정 전후 결과를 보존한다. 이는 실제 도착 기록이 아니다.

## 예비팀 대기열: 기존 편성 vs 합류 대기 자리 (2026-09-24)

위 시뮬레이터는 코트가 빌 때마다 네 명을 새로 고르는 모형이라 예비팀 대기열을 다루지 않는다. `queue.test.ts`는 운영진이 다음 팀을 `depth`개 미리 준비하는 보드 흐름을 **실제 보드 스토어 액션**으로 가상 시계에서 재생한다. 세션 스토어의 배정/완료만 픽스처이며 `complete_match`의 선수 갱신(대기 복귀·판수·혼복 판수·동반 이력·직전 유형)과 늦참 평균 판수 보정을 따른다.

- 운영 순서: 매 이벤트 후 빈 코트 카드 버튼(`autoFillTeam('court-N')`) → 네 명이면 경기시작 → 이탈로 깨진 일반 예비팀을 카드 버튼으로 보충 → 예비팀이 `depth`개가 될 때까지 새 팀 자동편성. `order: 'queue-first'`는 새 팀 편성을 코트보다 먼저, `tapFill`은 새 합류 대기팀의 카드 버튼을 바로 누른다(2026-09-25부터 `완료 후 채움` 비활성 표시라 아무것도 채우지 않는다).
- `legacy`: 새 팀을 `{ waitForCompletion: false }`로 편성한다. HEAD(ade2daa) 스토어로 같은 하네스를 돌린 결과와 1,212회 모두 경기 순서가 같다. `waiting`: 앱 기본값(`prefersWaitingDraft`).
- 교대 시간·호출 지연은 0이다. 따라서 미리 준비하는 것 자체의 코트 가동 이득은 측정하지 않는다. 도착은 첫 출전이 20분 넘게 늦은 사람만, 이탈은 마지막 기록 경기 종료 시각이다.
